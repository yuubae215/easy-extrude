# single-arm-pedestal-cell — 腕がペデスタルにめり込む配置 (ADR-145)

`examples/layout_pick_place_cell.json` (単腕ピック&プレイスセル) をワイヤ単位 (m) へ
直した受け入れフィクスチャ。**把持点自体はペデスタルから離れており、TCP の進入経路も
ペデスタルを通らない**のに、代表 IK 解の上腕 (shoulder→elbow) が台へ回り込む — という
ADR-145 が起票された症状そのものを再現する。

## 幾何 (mm 原典 -> m ワイヤ)

| 実体 | 原典 (mm) | ワイヤ (m) |
|---|---|---|
| `robot_pedestal` | 中心 (−120, 0, 860) / 300×300×120 | 外接球 center (−0.12, 0, 0.86) r 0.2205 |
| `robot_base` | (−120, 0, 920) = ペデスタル上面 | base (−0.12, 0, 0.92) |
| `part_bin` (供給ビン, 対象) | 中心 (200, 150, 875) / 200×150×150 | 上面 z = 0.95 の 9 サンプル |
| `output_tray` | 中心 (200, −150, 820) / 250×150×40 | 外接球 center (0.2, −0.15, 0.82) r 0.1471 |

障害物は front の `obstaclesExcluding` (`src/domain/graspTargets.js`) と同じ**外接球**
(箱の対角の半分) で作る。ここを箱で書くと、front が実際に送る形とは別のものを検査して
しまう。

## 受け入れ値 (`core/tests/test_templates.py` が固定)

| | `robot.kinematics` 宣言あり | 宣言を外した対照 |
|---|---|---|
| 生成候補 | 36 | 36 |
| 干渉棄却 | **4** | **0** |
| 通過 | 32 | 36 |

対照側が 0 であることが本テンプレの主張の本体である — **TCP 進入経路は一度も
ペデスタルに触れない**ので、4 件の棄却は腕リンクの FK スイープ (ADR-145) だけが
出せる差である。対照を置かないと「常に棄却する壊れたチェッカ」でも表の左側は緑になる。

ADR-145 起票時の値は **10 / 26** だった。ADR-150 D5 がフランジ x 軸の gauge を正し
(閉じ軸がフランジに固定される)、θ6 を含む代表解の選び方が 18 候補で別の枝を選ぶ
ようになった結果、上腕が台へ潜る枝が代表から 7 件外れ 1 件入った。旧値は誤った x 軸
に対して測った θ6 が代表を決めていた数である。

## 含めなかったもの (宣言)

`worktable` (600×500×800 @ z=400mm) は**外接球の半径が 0.559 m** になり、球の頂点
(z = 0.959) が供給ビンの把持点 (z = 0.95) を飲み込む。入れると全候補が既存の TCP
判定で棄却され、腕スイープの有無が見えなくなる。これは腕スイープの限界ではなく
**外接球という障害物表現の限界**で、厳密な箱/半空間は DEF-036 の担当。
