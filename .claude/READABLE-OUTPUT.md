# 読み手のために書く — コマンド出力の共通の形

`.claude/commands/` のコマンドが当事者に出す報告・俯瞰は、**リポジトリを見返さずに読んで判断できる**
ことを成果物の条件にする (当事者 2026-11-07: 「見返せばわかるけど、見返さないと分からない語彙が
突然出てきて分からないから聞き返すことが多い」「見出しの意味も分かりづらい。項目内に何が書かれた
集合なのかが頭に入りづらい」)。聞き返しが要る報告は、読み手の判断を遅らせる。

このファイルが形の正本。各コマンドは「何を並べるか」だけを自分で決め、語の規律と言い換え表は
ここを参照する (写さない — 写すと片方だけ直されてずれる)。問い所 = `src/ReadableOutput.test.js`。

## 1. 並び — 結論が先

1. **要約 (3 行以内)** — 何を見たか / いちばん重い結果 / 読み手が動くべきことが何個あるか。
2. **読み手が動くべきこと** — 当事者が決める判断、または直すべき指摘を、重い順に番号付きで。
   無ければ「なし」と書く (空欄にしない)。
3. **詳細** — 節ごとに。後ろの節は 2 を支える根拠で、2 と同じことを 2 度書かない (`→ 2 の 1 番` と指すだけ)。

## 2. 見出しの直後に「並ぶもの」を 1 行

見出しだけでは、その下に何の集合が並ぶのか分からない。各節の見出しの直後に書く:

> この節に並ぶもの: 〈何が〉〈何個くらい / 何ごとに 1 行〉

表を置くなら、この 1 行が表の 1 行の意味になる。表の列見出しも平易な言葉にする。

## 3. 語の規律

- **初出で言い換える。** 依頼文に出てこない語 (下の表の語・リポジトリ固有の名前・関数名・ファイル名・
  分類ラベル `DDD` `VISUAL` など) は、初めて使う所で括弧に平易な言い方を添える。2 回目以降は語だけでよい。
- **番号を主語にしない。** ADR 番号・原則番号・§番号・チェック項目の記号 (`D` など)・先例の日付は
  **根拠の札**であって説明ではない。文は番号を消しても意味が通るように書き、番号は文末の括弧に置く。
  - ✗「Rule violated: D」「ADR-101 の形なので §5 で 2 回通す」
  - ○「型で分岐していない — `dimension` の値で処理を分けているので、新しい種類を足すと黙って誤動作する (チェック項目 D / ADR-012)」
- **先例は 1 文で中身を言う。** 「ADR-098→101 の先例」と書くだけにしない。何が起きたかを 1 文添える。
- **指摘には「なぜ困るか」を添える。** 規則の名前だけでは、読み手は直す価値を判断できない。

## 4. よく出る内部語 → 出力での言い方

この表の語を出力で使うなら、初出に右列を添える。表に無い語でも、依頼文に出ていなければ同じ扱い。

| 内部語 | 出力での言い方 |
|---|---|
| 基数 (0 / 1 / N) | いくつあるか — 0 個 / 1 個 / 複数 |
| 権威 / 唯一の書き手 | その値を書き換えてよい唯一の場所 |
| 第二の源 | 同じ事実の写し (片方だけ直されてずれる元) |
| 導出 | 元の値から毎回計算して作る (自分では持たない) |
| 同一性の所有者 | 「どれのことか」を判定する関数の置き場所 |
| blast radius | 変えたときに影響が届く範囲 |
| census / 数え上げ | 対象を列挙して個数を数えるテスト |
| ratchet | 個数の上限・下限を固定し、増えても減っても落とすテスト |
| 線の問題 | 語はあるが、つなぐコードが無いだけ |
| 問い所 | その規則が守られているかを機械が確かめる場所 (テスト・CI・hook) |
| 段 (`S1b` など) | ADR の実装を分けた 1 回分の作業 |
| stale / fresh (証拠) | 証拠を取った後に関係するコードが変わった / 変わっていない |
| evidence debt | 主張のうち、まだ証拠で支えられていないものの割合 |
| no-op | 呼ばれても何もしない (空の) メソッド |
