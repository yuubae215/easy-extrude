# ADR-152 をフロントだけで評価する (バックエンド無し)

把持仕様・把持戦略・手の形 (ADR-152) を、**Python の `core/` も BFF も立てずに**触って
評価する手順と、記録の様式。GitHub Pages に出ているのと同じ**スタブのレーン**を使う。

## 何が評価でき、何ができないか (先に宣言する)

| 観点 | フロントだけで | 備考 |
|---|---|---|
| 語彙 — 仕様を名前つきで並べる・閉じ軸・深さ・許容傾き・戦略 | ✅ 本物 | パネル・文書・スキーマはフロントそのもの |
| 「+x ってどこ?」— 面チップの世界向きの語・面ラベル・ホバーの塗り | ✅ 本物 | 判定を含まない |
| 3D の確認 — 領域・進入矢印・接触面の縞・深さ面・開いた爪・手のプレビュー | ✅ 本物 | 描くのは送る値そのもの |
| 手の形 — tcp の手を宣言/未宣言、腕に描かれる手、取付けとの矛盾の停止 | ✅ 本物 | 停止はフロントのゲート |
| ワイヤ — 手と一致する仕様だけが優先順で載る、単位 mm → m | ✅ 本物 | `request` を画面の状態で確認できる |
| 判定の**向き** — x で挟むと開口不足 / y なら取れる / 深すぎると爪がテーブルに刺さる / priority と score の違い / 仕様ごとの行 | ✅ **粗い写し** | スタブ (`mocks/graspStub/solve.js`) が `core/` と同じ向きの答えを返す。`core/` が「取れない」と言う宣言を「取れる」とは言わない (`conformance.test.js` と e2e S13 が焼く) |
| 判定の**数値** — スコア、近さのメーター、筐体や進入経路途中の干渉 | ❌ | スタブは爪を把持姿勢で線分として見るだけ。筐体・進入線分上の手・IK は `core/` にしか無い |

数値まで確かめたいときだけ `pnpm dev:stack` (フルスタック) へ移る。

## 起動

```bash
pnpm install
pnpm dev:stub          # http://localhost:5173/easy-extrude/?graspStub=solve
```

マージ後は GitHub Pages (`build:stub`) でも同じものが触れる。

## 手順 (約 5 分)

1. 右上の **Adopt a context document.** → **Robot Cell — Robotics Checks** を選ぶ
   (把持の宣言は文書が持ち主 — 文書が無いと仕様を書けない。書こうとすると理由が出る)。
2. ロボット (`robot_base`) を選び、N パネルの **Grasp candidates…** を開く。
3. **Reached** カードの object で **ワーク** (80 × 40 × 60 mm、テーブルの上) を選ぶ。
4. **Grasped** カード — 読み込んだ文書の tcp は手が未宣言なので、`declare` を入れると
   既定の平行ジョー (開口 60 mm・筐体 78 + 爪 72 = 取付け 150 mm) が宣言され、腕の先の
   手が棒から筐体 + 爪に変わる。爪の長さを 30 にすると「TCP が爪の外」で Run が止まる
   ことも見る (戻しておく)。
5. **how to grasp** で `+ grasp spec` を 3 回押し、それぞれ:
   - `across x`: 進入 `+z · top`、close on `x`、depth `20`
   - `across y`: 進入 `+z · top`、close on `y`、depth `20`
   - `too deep`: 進入 `+z · top`、close on `y`、depth `70`
   面チップにマウスを乗せると、その面が 3D で塗られる。仕様を選ぶたびに、領域の輪郭・
   上からの矢印・接触面 2 枚の縞・深さ面・開いた爪の断面・手のプレビューが変わる。
6. **Run grasp search**。期待:
   - `by grasp spec` の行: `across x` 0 / `across y` > 0 / `too deep` 0
   - 候補はすべて `via across y` (priority — 最初に候補を持つ仕様だけ)
   - strategy を `score` にしても返るのは `across y` だけ (他は 0 件なので)。`across x` の
     closing を `y` にして `score` にすると 2 仕様が混ざる。
