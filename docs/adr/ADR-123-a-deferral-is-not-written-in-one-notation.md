## Context — Goal と力学 (§1.2 Goal)

**Goal:** *残しの個数が、それがどの記法で書かれていても数えられる。*

出発点はユーザーからの「ADR 未着手や、判断を残したものを教えて」→「管理面の見直しに
注力して」という指示である。ADR-109 の 5 つの問いは緑だった (宣言済み 9 / 宣言外 71 /
満期切れ 0 / 散文のみの満期 8)。**緑の外側に、統治されていない領域が 3 つあった。**
以下はすべて実測で、散文の転記ではない。

### 力学 1 — 母集団は語彙で導出したが、最大の登録簿は別の記法で書かれていた

ADR-109 は「登録簿を分母にしない」を正しく選び、母集団を残しの*語彙*
(`未着手` / `暫定` / `申し送り` / …) から導出した。ところが `docs/ROADMAP.md` は:

| 実測 | 値 |
|---|---|
| backlog 節 | 4 つ (frontend / Mobile UX / UX Polish / BFF Phase D) |
| 優先度マーカー付きの生きた行 | **29 行** (取り消し線を除く) |
| **残し語彙のヒット** | **0 件** |
| ここへ委譲している ADR | ADR-003 / 015 / 023 / 024 / 035 / 036 / 038 |

このリポジトリで最大の残し register は、**絵文字の優先度表と英語の "Backlog"** で
書かれており、語彙ベースの母集団に一行も入らなかった。ADR-109 §限界 は「英語で `TODO`
と書けば別の語彙」と正しく宣言していたが、実際に外れていたのは `TODO` という*語*では
なく**表という記法そのもの**である。語彙を 1 語ずつ足していく経路では、この 29 行には
永遠に届かない。

証拠が 1 つある。ADR-015 の Phase D は「Priority to be determined after Phase C
completion」と書かれ、その Phase C は **2026-04-15 に完了している**。満期はとうに
過ぎていた。誰も判定しなかったのは、それが母集団の外に在ったからである。

### 力学 2 — 除外の前提が実物と合っていなかった

登録簿 §覆えていないもの はこう宣言している:

> **Draft の ADR (ADR-043 / 044 / 046) は行を持たない。** `Draft` は「残し」ではなく
> 「まだ決めていない決定」であり、満期の対象が異なる (実装の遅れではなく判断の未成熟)。
> **これは推論ではなく宣言である。**

宣言としては正しい形をしている (推論させず、書き換え方まで指定している)。しかし
**宣言の根拠が 3 本中 2 本で偽だった**:

| ADR | 実測 | 未成熟か |
|---|---|---|
| ADR-043 | Phase 1〜4 すべて実装済み。ADR 本文の §Deferred (Phase 5+) は 3 項目とも自分で `✅ Implemented` と書いている | **否** |
| ADR-046 | Status 行自身が「MVP 実装 (`src/context/`, ゴールデンテスト 8/8) を反映」と書き、`**Implementation**` 欄まで持つ | **否** |
| ADR-044 | 名指しした `src/service/FunctionRegistry.js` / `FunctionMatcher.js` / `SpatialCommandParser` は**どれも存在しない** | 是 |

ADR-103 が名指しした退役の腐敗と同型である — **除外の腐敗も、違反を*見逃す*のではなく
緑を出す**。しかも今回は腐敗の向きが逆で、Status を上げ忘れた 2 本が「まだ決めていない」
という嘘を出し続けていた。台帳が実物より*遅れて*いたのではなく、実物が台帳を*追い越して*
いた。

### 力学 3 — 言及と実装は grep で区別できない (この ADR を書く作業が出した)

力学 2 を検査に降ろす最初の形は「Draft ADR を参照する `src/` ファイルの個数」だった。
これは **ADR-044 で偽陽性を出す** — `LayoutDslSchema.js` ほか 5 ファイルが文字列
`ADR-044` を含むが、いずれも φ 準同型の*実装*ではなく*言及*である。実際、この誤りは
最初の報告に一度出た (「Draft 3 本すべてに実装が在る」— 正しくは 2 本)。

ADR-109 §覆えていないもの が登録簿について宣言した「**言及と宣言を区別できない**」が、
そのまま検査の側にも居た。より賢い正規表現で解こうとするのは誤りである (実装の形は
ADR ごとに違うので、規則は ADR の数だけ要る)。**検査は数え、分類は宣言が持つ** —
ADR-100 の ratchet + 宣言表と同じ形に落とす。

### 力学 4 — 三つの register が三つの違う答えを出す

UX Polish の #73 (Modal a11y) について:

| register | 答え |
|---|---|
| GitHub Issues | `closed / completed` (2026-03-26)。**閉じた PR は 0 件** |
| `docs/ROADMAP.md` | 🟢 Low で**生きている** |

ROADMAP 冒頭の「Bugs are **also** tracked on GitHub Issues #69–#73」は二重管理を

## Options considered

- **A: ROADMAP を機械可読化して母集団に入れる** — tradeoff: 記法を 2 つ維持することに
  なる。完了記録と backlog が同居したままなので、次の記法もまた生える。力学 1 の
  再発を防がない。
- **B: register を 1 本に畳む (登録簿のみ)** — tradeoff: ADR-109 D5 の警告
  (「レーンが違う残しを表から外さない」) に最も忠実。しかし登録簿が 38 行の backlog に
  なり、「設計判断を伴う残しの索引」という設計意図から外れる。催促の速度が違うものを
  同じ表に入れると、速い側が遅い側のノイズになる。
- **C: register を 2 本にし、粒度で分け、両方を母集団の中に置く【採用】** —
  tradeoff: 分けた瞬間に「母集団の外」が再生産される危険 (D5 の警告そのもの) がある。
  これを D2 の**委譲行**で塞ぐ。分けること自体ではなく、*黙って*分けることが欠陥である。
- **D: Draft を母集団に入れず、census だけ足す** — tradeoff: 安い。しかし
  「Draft のまま何も起きない」を止められない。ADR-043 は Draft のまま 2 か月半、
  ADR-044 は 2 か月経っていた。除外の根拠が偽だと分かった以上、除外を維持する理由が無い。

## Decision — Strategy (§1.2 Strategy)

### D1 — `docs/ROADMAP.md` を凍結アーカイブにする

`docs/SESSION_LOG.md` と同じ扱いにする (追記しない / そこに書かれた残しは当時の記録で
あって今日の残しではない)。`check-deferrals.mjs` の `EXCLUDED` に**理由つきで**登録する。

**数の上では何も変わらない** (語彙ヒットが元から 0 件だったので)。変わるのは、外れて
いることが**宣言になる**ことである。黙って外れているあいだは、「登録されていない」と
「登録する必要が無い」が区別できなかった (原則 #31)。

生きた行は記法ごと移す。移す先は**残しの内容の正本**であって登録簿ではない
(登録簿は索引 — ADR-109)。すなわち、決定を所有する ADR の本文に、**残しの語彙で**
宣言を書き、登録簿はそこを指す。

### D2 — 残しの register を 2 本にし、委譲を 1 行で宣言する

| register | 対象 | ticket |
|---|---|---|
| `docs/DEFERRAL_LEDGER.md` | **設計判断を伴う残し** | ADR 番号か段 (必須) |
| GitHub Issues | **機能要望** (設計判断を伴わない) | issue 番号 |

ADR-109 D5 は「レーンが違う残しを表から外さない — 外した瞬間に母集団の外が
再生産される」と警告している。**この警告は分けることではなく黙って分けることを
禁じている**、と読む。よって登録簿に **委譲行** を 1 本置き、そこが Issues レーンの
存在と現在の委譲対象を宣言する。

**限界を宣言する (推論させない):** 委譲行が覆うのは*委譲の事実*であって *Issue の
個数*ではない。個数はネットワークの向こうに在り、CI はオフラインで走るので数えない。
力学 4 が示したとおり Issues も独立にドリフトしうるが、**その照合は今日も人がやる**。
ここは埋めていない穴として置く。

### D3 — Draft は「判断の未成熟」ではなく「判断の未完了」であり、満期を持つ

登録簿 §覆えていないもの の Draft 除外段落を書き換える (段落自身が「将来 Draft を
残しとして扱うなら、行を足すのではなくこの段落を書き換えること」と指定しているので、
その指定どおりに行う)。

Draft / Proposed の ADR は残しの母集団に入り、登録簿に行と満期を持つ。満期は
「実装が入ったとき」ではなく **「判断が閉じたとき」** で書く — Draft の残しは
実装の遅れではなく決定の未完了だからである。この区別は維持する (ADR-109 の
洞察は正しく、偽だったのは「Draft = 未成熟」という*当てはめ*のほうである)。

### D4 — Draft の実装先行を数える (Q6)。検査は数え、宣言が分類する

- **母集団** = Status ヘッダから導出した Draft / Proposed の ADR 集合。
  `check-adr-status.mjs` と**同じ文法**を使う (第二のパーサを作らない — Q2 の先例)。
- **数えるもの** = `src/` / `core/` / `server/` から当該 ADR を参照するファイルの個数。
- **既定は 0。** 非ゼロは `DRAFT_WITH_IMPLEMENTATION` に**理由つきで宣言**した行だけ許す。
- **逆向きも問う** — 宣言した行の参照が実在しなくなったら落とす (ADR-103)。

宣言欄が要点である。無ければ人は Status を `Accepted` に倒して緑にし、**台帳に嘘が
入って今より悪化する**。「実装が先行してよい Draft」は実在する — ADR-046 の MVP は
実装して初めて DSL の形が決まった。**gate (マージ拒否) を採らないのはこのため**で、
gate が最初から在ったら ADR-046 は書けなかった。今回の 2 件も gate では 1 件も
防げない (どちらも実装先行ではなく Status の上げ忘れ)。

宣言欄は同時に力学 3 への答えでもある。個数は機械が数え、「これは言及であって実装では
ない」という判断は人が 1 度だけ書く。

### D5 — 満期 trigger の文法を拡張する

`満期=ADR-NNN` に 2 形を足す。どれも**登録簿の満期欄に書ける token** である。

| 形 | 満期の意味 |
|---|---|
| `満期=ADR-NNN` | その ADR が `Accepted` になったとき |
| `満期=PATH:<path>` | そのパスが**存在するようになった**とき |
| `満期=GREP:<path>::<正規表現>` | そのファイルにパターンが**現れた**とき |
| `満期=GONE:<path>::<正規表現>` | そのファイルからパターンが**消えた**とき (**実装中に足した 4 形目** — §実装で分かったこと 1) |

DEF-013 の満期「`core/tests/test_engine.py` に検査が入ること」は、条件としては完全に
機械可読なのに文法が無いという理由だけで散文に落ちていた。**満期を*書く欄*を作った
ことと、その欄を*読む機械*が在ることは別の事実である** (ADR-109 D6 と同じ形が、
条件の*種類*の側にもう一度居た)。

「nightly Rust が安定化したとき」のような外部条件は依然として書けない。Q5 の予算は
その分だけ残る — **書けないこと自体は正当**だが、黙って 0 件に見えることは許さない。

## 実装で分かったこと (2026-08-12)

書いてみて初めて出たものを、決定の後ろに正直に足す。

### 1 — 満期の 4 形目 `GONE` が要った (D5 は 3 形で書かれている)

DEF-008 の満期は「`DECLARED_GAPS` が空になったとき」で、当の
`src/DanglingSelfCallCensus.test.js` 自身が「表が空になったら `DECLARED_GAPS` ごと
消す」と書いている。つまり満期は**出現ではなく消滅**だった。「残しが片付いたとき」
という**最も普通の満期の形**が、出現を待つ 3 形では原理的に書けない。
`満期=GONE:<path>::<regex>` を足した。

副次的な制約も出た: 正規表現に**リテラル空白と `|` を書けない** (登録簿は Markdown の
表なので `|` はセル区切りとして食われる)。`\s` は使えるので実用上は足りる。

### 2 — 「同じ文法で読む」はコメントに書いてあっただけだった

`check-deferrals.mjs` の Q2 は「指す ADR の Status を `check-adr-status.mjs` と
**同じ文法**で読む (第二のパーサを作らない)」とコメントしていた。**実物は違った** —
ローカルに書き写された正規表現は 4 方言のうち**表形式 `| **Status** | X |` を読めず**、
ADR-027 / ADR-032 などがマップから丸ごと欠落していた。

欠落は「Status が不明」ではなく **「その ADR は存在しない」** として現れる。実際
Q3 が「ticket ADR-027 が docs/adr に存在しない」と報告した (実在するのに)。
**意図を宣言したことと、実物がそうであることは別の事実である** — ADR-115 が
「印字は検査ではない」で数えたのと同じ形が、「コメントはパーサではない」として出た。

露見の条件が重要である: **初めて表形式の ADR を ticket に持つ行 (DEF-017 / DEF-018) を
足した日**に出た。それまで 2 つのパーサの差は誰にも当たっておらず、検査は緑だった。
文法は `scripts/adr-status.mjs` へ切り出し、両者がそこを引く形にした (§1.1)。

### 3 — パーサを直した瞬間に、台帳と実物の食い違いが 1 件出た

`ADR-032` (Geometric Host Binding) は **header が `Proposed`、索引 (`docs/adr/README.md`)
が `Accepted`、実装は 13 ファイル** (`FastenFrameCommand` / `MountAnnotationCommand` ほか)
という三様のずれを起こしていた。しかも ADR-035 は本 ADR を前提に Accepted 済みである。

これは力学 2 と同じ「実物が台帳を追い越す」形だが、**表形式だったので旧パーサからは
見えなかった**。読めない方言があることは、その方言で書かれた ADR が*検査の外に
在る*ことを意味していた — 記法の違いが母集団を削るという力学 1 が、ADR 本文の側にも
居たわけである。header を Accepted へ是正した。

## Lens notes

- **§1.1 真実の源は一つ** — ROADMAP は「完了 phase の記録」と「生きた backlog」の
  二役を兼ねていた。前者は SESSION_LOG と同じ凍結物、後者は登録簿と Issues。
  役が 2 つある文書は、どちらの源でもないまま両方をドリフトさせる。
- **原則 #31** — 数えるべきは在る行ではなく*表が覆えていない*個数、という ADR-102 の
  規律は正しく適用されていた。破れていたのは一段上で、**母集団を導出する鍵 (語彙) が
  記法を仮定していた**。導出は「人の記憶を権威から外す」ことには成功したが、
  「記法の選択」という別の権威をそのまま残していた。
