# 112. 文書の入口の住所を恒久にする — 満期の過ぎた暫定を、更新ではなく決着で畳む

- Status: Proposed (ADR-106 D3 の暫定住所の満期 = ADR-108 は過ぎた。本 ADR がその決着。IA Phase 5.2)
- Date: 2026-08-04
- Deciders: yuubae215, Claude
- Supersedes / Superseded by: なし (ADR-106 D3 の**暫定**を恒久へ確定させる。
  ADR-108 が決めた入口 (`START` の `GUIDED_INTAKE` 行) は不変 — 決めるのは器の住所)

## Context — Goal と力学 (§1.2 Goal)

**Goal:** *文書を書いている最中に、いま書いたものがどう効いたかが見えている。*
そして暫定であることの宣言が、決着によって畳まれる (満期切れのまま生き続けない)。

### 力学 1 — 満期は過ぎている (これが起票の直接の理由)

`src/view/DocIntake.js:54`:

```js
export const PROVISIONAL_UNTIL = 'ADR-108 (IA Phase 5 — 入口の統合)'
```

ADR-106 D3 は Wizard / Intake を場のタブから出すとき、2 点だけを決めた —
(1) 場のタブではない、(2) Phase 5 まで到達可能な暫定の住所を持つ。そして
「宣言しない暫定は恒久になる」という正しい認識のもと、暫定であることをコードに置いた。

**ADR-108 (Phase 5) は入口を決めたが、器の住所を決めなかった。** 満期は過ぎ、
何も落ちなかった。同じポインタは 7 箇所に写されており、7 箇所すべてが同時に古くなった
(ADR-109 §力学 1 が実測を持つ)。

### 力学 2 — 満期が空振りしたのは、条件が**別の判断**に置かれていたから

ADR-106 は「入口を統合する段が、器の住所も決めるだろう」と見込んだ。実際には
ADR-108 が扱ったのは**動詞と対象の直積**であり、器の住所はその直積に現れない。
入口 (`START` → `GUIDED_INTAKE` → `onWizardStart`) は Phase 5 で確定しているが、
**その入口が開く器がどこに住むか**は同じ判断の中に入っていなかった。

> 満期の条件を「別の判断が起きること」に置くと、その判断が自分を含む保証は無い。

これは ADR-109 D3 (満期は機械が読む) の必要性を作った実例であり、同時に**満期条件の
書き方**の教訓でもある: 満期は「誰かが決める」ではなく「**この問いが決着する**」で
書かねばならない。本 ADR がその決着であり、以後この住所は暫定ではなくなる。

### 力学 3 — 今日の住所の根拠は、実は既に強い

`src/components/Doc/DocIntakeLayer.jsx` は左側にドックする**一時オーバーレイ**で、
3D と N パネルを見せたまま Outliner だけを一時的に覆う。この形が選ばれた根拠は
2 つとも今日も有効である:

- **モーダルではない** — `IntakePanel` は `onIntakePreview` で 3D に不確かさバンドの
  ゴーストを出す (ADR-051 Entry D)。全面モーダルはそれを覆い、「入力の検算 =
  エコーバック」という 3D の責務が消える。
- **常設ではない** — 画面端の予算 (原則 #26) を食わない。TemplateGallery と同じ扱いで、
  ADR-050 が既に採っている区別。

つまり暫定だったのは**住所そのものが疑わしかったから**ではなく、「Phase 5 が入口を
決めるとき一緒に見直すべきかもしれない」という**手続き上の留保**だった。留保は
果たされ、見直す理由は出てこなかった。

### 力学 4 — ただし ADR-111 が新しい論点を 1 つ作る

今日の住所は「**Outliner を覆う**」ことを選んでいる。それが安全だったのは、
Outliner が幾何の木であり、文書と関係が無かったからである。

ADR-111 (Outliner の意味側) が入ると、その前提は崩れる — **意味側は、いま入力して
いる文書の共有変数を映す面**になる。フォームを埋めながらそれが覆われていると、
3D のゴーストと同じ理屈でエコーバックが 1 つ消える。

したがって本 ADR の決定は ADR-111 の後でなければ完全にならない。順序表でも
Phase 3.6 (ADR-111) → Phase 5.2 (本 ADR) と置く。

## Options considered

- **A: 暫定のまま満期だけ延長する (`PROVISIONAL_UNTIL` を次の Phase へ張り替える)** —
  tradeoff: 実装ゼロだが、**暫定を暫定で更新する**のは決着の先送りである。ADR-106 の
  GSN が `ProvisionalAddressesStayProvisional` を反証されうる仮説として持っていた —
  この案はその仮説を反証しにいく側 (暫定が既定の導線として定着する) そのもの。
- **B: 今日の住所をそのまま恒久化する (覆う範囲も現状のまま)** — tradeoff: 力学 4 を
  見なかったことになる。ADR-111 が入った日に「フォームを埋めると意味側が見えない」が
  必ず起きて、踏んだ人がその場で最小の回避策を書く。
- **C: 今日の住所を恒久化し、覆う範囲に規則を与える (採用)** — tradeoff: 覆う範囲の
  規則という新しい取り決めが 1 つ増える。ただし規則の所有者は 1 つ (下の D2) で、
  呼び出し箇所ごとのパッチにはならない。
- **D: 下部の器 (場) へ戻す** — tradeoff: ADR-106 D3 が「器に残るのは**解消とその記録**
  だけ」と決めた線を、入力を戻すことで崩す。**却下** (器と中身の形の不一致が再発する)。
- **E: 全面モーダルにする** — tradeoff: ADR-051 Entry D のゴーストを覆う。**却下**
  (力学 3 の 1 点目)。

## Decision — Strategy (§1.2 Strategy)

**案 C。** `DocIntakeLayer` を**恒久の住所**とする。暫定は延長ではなく決着で畳む。

### D1 — `PROVISIONAL_UNTIL` を消す (更新しない)

決着した以上、暫定の宣言は残さない — 残せば ADR-109 §力学 2 が名指しした「完了しても
生き残る宣言」を自ら作ることになる。消すのは **7 箇所すべて**で、消し残しは
ADR-109 D4 の逆向き検査が数える。

**本 PR では消さない** — 本 ADR はまだ Proposed だからである。本 PR がやるのは
**満期のポインタを ADR-108 から本 ADR へ張り替えること**だけで、これは実装ではなく
「満期が過ぎたまま緑を出している状態」を止める最小の是正である。

### D2 — 覆う範囲の規則を 1 箇所に置く (力学 4 への答え)

一時オーバーレイが覆ってよいのは「**いま入力しているものを映していない面**」だけ、
という規則にする。今日の実装は「Outliner を覆う」という**面の名前**で書かれているが、
ADR-111 の後は面の名前では規則を表せない (同じ Outliner の中で、幾何側は覆ってよく
意味側は覆えない)。

したがって規則の書き方を**面の名前から役割へ**変える。所有者は 1 つ
(`src/view/DocIntake.js` の宣言表) で、未宣言の面では throw する — 3 面目が生まれた日に
既定へ落ちない (原則 #31 / ADR-096 の既定表の規律)。

### D3 — 入口は動かさない

`START` の `GUIDED_INTAKE` 行 (`onWizardStart`, `requires: CONTEXT_DOC`) は ADR-108 が
決めたとおり不変。**器が動いても入口は増えない**という ADR-106 / ADR-108 の接点は、
恒久化した後もそのまま成り立つ。ヘッダの入口の個数 (desktop 7 / mobile 7) は動かない。

### D4 — 台帳の行を「暫定」から「恒久」へ

`docs/STATE_LEDGER.md` の `文書の入口 (docIntake)` 行は、値域 (`wizard` / `intake` +
不在 = 3)・基数 (0..1)・権威 (`ContextService.loaded`) はそのままに、
**`PROVISIONAL_UNTIL` が宣言していた暫定性の欄だけ**が畳まれる。状態機械は起こさない
(3 値だが不正遷移が事故にならず、遷移は「開く / 面を替える / 閉じる」のみ)。

## Consequences — Evidence と tradeoff (§1.2 Evidence)

- **肯定的:** 満期の切れた暫定が 1 件消える。7 箇所のポインタが同時に古くなる構造が
  終わる。ADR-106 の GSN の仮説 `ProvisionalAddressesStayProvisional` に**反証されな
  かった**という結末が付く (暫定は恒久化されたが、それは*決着として*であって、
  なし崩しにではない — この 2 つを区別することが仮説の眼目だった)。
- **受け入れるコスト:** 覆う範囲の規則が 1 つ増える (D2)。これは ADR-111 が入って
  初めて意味を持つので、**ADR-111 より先に本 ADR を実装すると規則が空回りする** —
  順序表の依存として明示する。
- **受け入れるコスト (正直な限界):** 恒久化しても、この面が「文書を編集する唯一の場所」
  であるとは決めていない。N パネルからの文書編集 (ADR-104 の提案経路) は別に在り、
  「どの編集がどちらに住むか」は本 ADR の範囲外である。**範囲外であることを宣言する** —
  推論させない。
- **検証 (証拠):** `docs/gsn/adr-112-the-document-intake-address-becomes-permanent.gsn`。
  実装時の証拠は 3 つ — (1) repo 内に `PROVISIONAL_UNTIL` を名乗る宣言が **0 個**
  (ADR-109 D4 の逆向き検査)、(2) 未宣言の面で throw する (unit)、(3) 入力中に意味側が
  覆われない (e2e — ADR-111 実装後)。**現時点ではすべて未来形** (Proposed の理由)。
- **波及 (blast radius):** `src/view/DocIntake.js`、`src/view/FloorTabs.js`
  (`RETIRED_FLOOR_TABS` 2 行の注記)、`src/components/Doc/DocIntakeLayer.jsx`、
  `src/store/uiStore.js`、`src/controller/ContextController.js` (2 箇所の注記)、
  `docs/STATE_LEDGER.md` 1 行、ADR-106 本文の相互リンク。
  **挙動を変えるのは D2 (覆う範囲) だけ**で、他はすべて宣言の畳み込みである。

## Lens notes

- **§1.2 満期条件の書き方:** 力学 2 の教訓を一般形で言うと「*満期は、自分の問いが
  決着する事象に置く。他人の判断に相乗りしない*」。ADR-109 D1 の登録簿が満期を
  **条件**として持つのはこのためで、日付では同じ空振りを検出できない。
- **原則 #26 (画面端は共有資源):** 一時オーバーレイは端の予算に**入らない**という
  ADR-106 の判断は恒久化後も不変 — `EdgeOccupancy` の段に行は増えない。
- **§1.3 黒箱:** `WizardPanel` / `IntakePanel` の入力→出力は不変。変わるのは容器の
  可視性の規則だけで、パネルは自分がどこに住んでいるかを知らないままである。
