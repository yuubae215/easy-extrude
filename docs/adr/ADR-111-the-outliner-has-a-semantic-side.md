# 111. Outliner に意味側を与える — 選べるのにどのナビゲータにも載っていない実体を無くす

- Status: Accepted (実装済み 2026-08-05 — IA Phase 3.6。`SelectionOwnership.test.js` は**作り直さずに**通り、入口は 5 verb のままだった)
- Date: 2026-08-04
- Deciders: yuubae215, Claude
- Supersedes / Superseded by: なし (ADR-107 が広げた選択の**要素の種**に、ADR-099 が
  決めた「入口は 5 verb のまま」を保ったまま**窓**を 1 つ与える。選択モデルは不変)

## Context — Goal と力学 (§1.2 Goal)

**Goal:** *選べるものは、どれかのナビゲータに載っている。* 左のナビゲータを見れば
「このシーンで何が選べるか」が尽くされていて、選択の種が増えてもそれが崩れない。

### 力学 1 — 選べるのに、どこにも載っていない実体が実在する

ADR-107 (Phase 3.5、実装済み) は選択集合の要素を 2 種に広げた:

```
Selection = { kind:'empty' }
          | { kind:'entities',  ids:  Set<entityId> }
          | { kind:'variables', refs: Set<variableRef> }   ← ADR-107 で追加
```

`variables` は今日**選べる** — 場の行列の変数見出しをクリックすると選択の種が入れ替わり、
3D に未確定帯が出て、N パネルの中身が `NPanelVariable` に替わる (e2e 2 本が焼いている)。

しかし `src/components/Outliner/Outliner.jsx` (463 行) には**意味側が無い**。
幾何 ⇄ 意味のトグルも、共有変数の一覧も無い。結果として:

> **`d_ref` は選べるのに、左のナビゲータには存在しない。**

v8 注釈② はこれを先に見抜いて、こう書いている:

> 『d_ref を選んだら d_ref がアクティブになる』を通すと、**選択できるのにどの
> ナビゲータにも載っていない実体**が生まれてしまう。文書の変数は**意味の層の住人**
> なので住所はここ。

つまりこれは「あると便利な機能」ではなく、ADR-107 を出荷したことの**帰結として
生まれた穴**である。

### 力学 2 — この項目は 2 回、段を持たないまま送られた

- ADR-107 §実装で変わったこと: 「Outliner の意味側 (v8 注釈②) は**未着手**」。
- `03-implementation-order.md` §Phase 3「この段が引き受けなかったもの」:
  Phase 3 は器の住所だけを扱ったので入っていない、次は「Phase 3.5 の延長として起票せよ」。

**混ぜなかった判断は正しい** — 意味側は「幾何の木の隣に文書の木を並べる」話で、
下端の占有とも右端の排他とも関係が無い。Phase 3 に混ぜれば 2 つの判断が 1 つの PR で
不可分になっていた。

正しくなかったのは、その正しい判断が**散文にしか residence を持たなかった**ことである。
`scripts/check-adr-status.mjs` は「段を持たない ADR」を数えるが、粒度が ADR 単位なので
ADR の**中の 1 項目**は見えない。この ADR はその項目に段を与えるためのものであり、
同時に ADR-109 (残しの登録簿) が生まれた 4 つの実例のうちの 1 つである。

### 力学 3 — 今の Outliner は「幾何の木」であって「ナビゲータ」ではない

現状の Outliner は実体の階層をそのまま描く (`TYPE_ICON` は cuboid / sketch / frame /
annot-* — すべて 3D に体を持つ)。ADR-103 が Lynch 5 種 (⟿⬡) を Map から `+ 追加` へ
移したとき、**それらは幾何側に同居した** — 体を持つからである。

文書の変数は体を持たない。3D の姿は「未確定帯」という**投影**であって体ではない
(ADR-107 が 3 通りに割ったうちの 1 つで、スカラーには帯すら無い)。体を持たない住人を
幾何の木に混ぜると、木の意味が「在るものの構造」から「選べるものの一覧」へ静かに
変わる — それは同じ 1 つの木に 2 つの意味を持たせることになる (§1.1)。

```mermaid
graph LR
  subgraph 左 = 選ぶ
    G["幾何側 (既定)<br/>体を持つ実体の階層"]
    S["意味側 (本 ADR)<br/>文書の住人 — 共有変数"]
  end
  subgraph 中央 = 触る
    V["3D ビュー"]
  end
  subgraph 右 = 編集
    N["N パネル<br/>種で中身が替わる (ADR-107)"]
  end
  G -->|selectOnly| N
  S -->|selectOnly| N
  S -.->|未確定帯 / DIMMED| V
  G --> V
```

## Options considered

- **A: 共有変数を幾何側の木に混ぜる (末尾のグループとして)** — tradeoff: 実装は最小
  (1 グループ足すだけ) だが、力学 3 のとおり木の意味が 2 つになる。「在るものの構造」を
  読みに来た人が、体を持たない行に出会う。ADR-103 が ⟿⬡ を幾何側に置けたのは
  **体を持つから**であって、「文書由来だから意味側」ではない — 基準は住所の層である。
- **B: 変数は N パネルからしか触れないままにする (現状維持)** — tradeoff: 選べるのに
  載っていない実体が残る。しかも場を閉じると変数を選ぶ窓 (行列の見出し) が画面から
  消えるので、**変数を選ぶには必ず場を開く**必要が残る — ADR-105 が断ったのと同型の
  循環 (場に入らないと場の中のものが触れない) が、選択の側で生き残る。
- **C: 左のナビゲータに幾何 ⇄ 意味のトグルを置き、意味側に文書の住人を並べる (採用)** —
  tradeoff: トグルという**モードが 1 つ増える**ように見える。これは表示の切替であって
  実体の状態ではない (下の D3 で境界を引く)。Blender の Outliner 表示モード /
  Figma の Layers ⇄ Assets と同型で、v8 注釈② が既に採った案。
- **D: 意味側を第三のドックとして常設する** — tradeoff: 画面端の予算 (原則 #26) を
  1 つ食う。ADR-106 が右端の奪い合いを住所で解いた直後に、左端で同じ奪い合いを
  始めることになる。**却下。**

## Decision — Strategy (§1.2 Strategy)

**案 C。** 左のナビゲータは 2 つの側を持つ。既定は幾何側 (初期頻度 — 関係性の論理は
最初は考えない)。

### D1 — 意味側の住人は「文書の共有変数」から始める

`context.doc.variables[]` (`ref` / ラベル / 単位 / 束縛されている実体) を並べる。
**今日並べるのは変数だけ**である。actors / requirements / KPI も文書の住人だが、
それらは*選択できない*ので、載せると「載っている ⊃ 選べる」が崩れて力学 1 の逆
(載っているのに選べない) を作る。

### D2 — 意味側の行は**窓**であって入口ではない

行のクリックは `SelectionManager.selectOnly(variableRef(ref))` を呼ぶ。ADR-099 が決めた
**5 verb の入口はそのまま**で、窓が 1 つ増えるだけである。検算は ADR-107 が使ったのと
同じ形 — `src/SelectionOwnership.test.js` の母集団の作り方を**変えずに**通ること。
作り直しが要ったら、それは選択に第二の書き手を作った証拠である。

### D3 — トグルは「表示の側」であって実体の状態ではない (台帳に載せる)

`outliner.side ∈ {geometry, semantic}` は UI transient で、**基数は常に 1**
(側を持たない Outliner は無い)。`docs/STATE_LEDGER.md` に行を足すが、状態機械は
起こさない — 2 値・不正遷移が事故にならない・導出でもないので、核 §1.4 の閾値を
跨がない。**閾値未満でも台帳には記録する** (記録しなければ累積しない)。

### D4 — 意味側が空のときは 0 を宣言する (既定値で埋めない)

文書が無いとき / 文書に変数が 0 個のときは**別の 0** である (ADR-105 が発見の 0 を
4 種に割ったのと同じ)。最低 2 種を宣言する:

| 0 の種 | 意味側が言うこと |
|---|---|
| 文書が無い | 「文脈文書がまだ在りません」+ 採択への出口 (ADR-105 の `unexamined` と同じ先) |
| 文書に変数が 0 個 | 「この文書は共有変数を宣言していません」 |

**「空」で両方を賄わない** — 原則 #31 / ADR-096 の既定表の規律。

## Consequences — Evidence と tradeoff (§1.2 Evidence)

- **肯定的:** 「選べるもの ⊆ どれかのナビゲータに載っているもの」が成り立つ。
  場を閉じたまま変数が選べるようになり、力学 2 の残った循環が消える。
- **肯定的 (将来の種に効く):** 3 種目の選択可能種が来たとき、「どのナビゲータに載るか」
  という問いが**既に構造として在る** — 幾何側か意味側かを決めればよい。今日それが
  無いから、ADR-107 は種を足した瞬間に穴を開けた。
- **受け入れるコスト:** Outliner に側が増え、幾何側しか使わない人にとってはトグルが
  1 つ増える。既定が幾何側であること (v8 注釈②) がこのコストの上限を決める。
- **受け入れるコスト (正直な限界):** 意味側は文書に依存するので、**文書を採らない
  使い方**では常に D4 の 0 状態である。それを「空のパネル」ではなく宣言として出す分の
  実装が増える — が、そこを削ると ADR-105 が潰した「未検証と問題なしの混同」を
  ナビゲータ側で再生産する。
- **検証 (証拠):** `docs/gsn/adr-111-the-outliner-has-a-semantic-side.gsn`。実装時の
  証拠は 4 つ — (1) `SelectionOwnership.test.js` が**作り直さずに**通る、
  (2) 選択可能な種のうちナビゲータに住所を持たないものが **0 個** (種を列挙して数える
  — 在る行を辿らない)、(3) 場を閉じたまま意味側から変数を選べる (e2e)、
  (4) 文書なし / 変数 0 個の 2 種の 0 がそれぞれ別の文言を出す (unit)。
  **現時点ではすべて未来形** (Proposed の理由)。
- **波及 (blast radius):** `src/components/Outliner/Outliner.jsx` (側の切替 + 意味側の
  行)、`src/view/` に側の宣言表 (未宣言の側で throw)、`src/store/uiStore.js`
  (`outliner.side` + 単一の書き手)、`docs/STATE_LEDGER.md` 1 行、
  `docs/SCREEN_DESIGN.md` の Outliner 節。**ドメイン・選択モデル・契約は不変。**

## Lens notes

- **§1.1 ドメイン境界:** 幾何側の住人は `src/domain/` の実体、意味側の住人は
  `context.doc` の宣言。**同じ木に混ぜない**のは、2 つの bounded context を 1 つの
  ナビゲータが所有してしまうのを避けるため (案 A の却下理由の言い換え)。
- **原則 #31:** 数えるべきは「意味側に何行あるか」ではなく「**選択可能な種のうち、
  ナビゲータに住所を持たない種の個数**」。今日それは 1 (variables) で、在る行を
  辿る数え方では 0 に見える。
- **原則 #15 (Fixed Slots):** 意味側は文書が無くても**消さない**。消すと「文書を採る
  前は意味の層が存在しない」という誤ったモデルを教えることになる (D4)。

## 実装で変わったこと (2026-08-05)

### 「文書を採ったか」は述語 1 つに畳んだ (検査が先に見つけた)

意味側は「文書が在るか」を読む。素直に `context.discovery.kind !== UNEXAMINED` と
書いたところ、`DiscoveryOutsideTheFloor.test.js` が落ちた — Outliner は下端の占有量を
引くために場の開閉も読んでおり (原則 #26 — 正当)、集約の描き手が場の開閉に触れる形に
なったからである。

**回避ではなく、検査が先に見つけたものを直した。** 同じ導出は既にヘッダにも書かれて
いたので、この 1 行は**書かれた瞬間から第二の源**だった (§1.1)。`view/DocPresence.js`
の `documentAdopted(state)` に畳み、両方がそれを読む。副作用として Outliner は集約を
読まなくなり、2 つの正当な読みの交差も消えた。

### `variables` の書き手を場から文書の辺へ移した (e2e が捕まえた)

`contextSetVars` は `_reproject()` の `negotiate` 分岐の中だけで呼ばれていた。読み手が
場の中の dropdown 1 つだけだったあいだは十分だったが、意味側は**場の外から**読む。
書き手を `_refreshDocReadModels()` (文書の辺 = `contextLoaded` / `contextChanged`) へ
移した — 場に閉じた書き手のままだと、ADR-105 が断った循環 (場に入らないと場の外で
選べるものが見えない) が選択の側で再生産される。

**さらに `contextEnd` が `variables: []` を書いていた。** これは ADR-105 D4 が名指しした
形そのもの — ライフサイクルのリデューサが、自分の所有でない導出値を書いている。
「場を閉じた」は文書が変数を持つかどうかが変わる理由ではない。読み手が場の中だけの
あいだは無害だったので、静的な検査では見えなかった: **捕まえたのは e2e**
(「場を閉じたまま意味側から共有変数を選べる」) である。

### 幾何側の名前は変えなかった

側のラベルを短くしたくなるが、`Scene Collection` は既に ubiquitous language で、
ツアーの文面 (`TourMath`) と `CODE_CONTRACTS` の e2e 節がこの名前を指している。
側を足したことを理由に既存の概念を改名すると、同じものに 2 つ目の名前が生まれる
(§1.1 — 一概念一名)。ラベルはそのまま、スイッチ側の字送りで収めた。
