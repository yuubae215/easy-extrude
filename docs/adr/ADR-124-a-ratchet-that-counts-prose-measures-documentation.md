# 124. 散文を数える ratchet はドキュメント量を測っている — 指標を 0 へ向かえる数に戻す

- Status: Accepted (実装済み 2026-08-12 — 下記 §実装で分かったこと)
- Date: 2026-08-12
- Deciders: yuubae215, Claude
- Supersedes / Superseded by: なし。ADR-109 の Q1 の**測り方**と、ADR-123 が塞ぎ残した
  再発経路を扱う。登録簿・7 つの問い・ratchet の姿勢はそのまま

## Context — Goal と力学 (§1.2 Goal)

**Goal:** *統治の数字が「片付ければ減る」量を測る。* そして、同じ失敗形が次に起きた
ときに**人の記憶ではなく機械が**気づく。

出発点はユーザーからの 3 つの問いである — 「deferrals の個数は今後増えていくだけ?」
「Issue 化して節を消せば決着、が分からない」「これらって運用にフィードバックしてほしい。
また起こるでしょ?」。3 つとも当たっていた。

### 力学 1 — ratchet がドキュメント量を測っていた

ADR-123 は Q1 の baseline を 71 → 99 へ上げ、「決着を*記述する*散文が増えたから」と
説明した。説明は正しいが、**そこで止まったのが誤りだった**。内訳を測ると:

| 場所 | 件数 |
|---|---|
| `docs/adr/` の散文 | **68** |
| `docs/` その他 | **29** |
| **`src/`** | **1** |
| `scripts/` | 0 |

**コードに残っている残しは 1 件**で、98 件は残しについて*述べている*文だった。
つまりこの数は **残しを片付けても減らず、残しについて考えるほど増える**。
ADR-100 の ratchet は「宣言外は 0 であるべきだが今は N 件ある」という形を持つが、
**0 へ向かえない数に ratchet を掛けても、それは予算ではなく体重計である**。

2026-08-05 に Yellow Cards へ記録した粒度の欠陥 (言及と宣言を区別できない) は、
「baseline がときどき上がる」程度の話として扱われていた。実測したら**指標そのものが
無効化されるところまで来ていた** — 悪化の速度を測っていなかったので気づけなかった。

### 力学 2 — 塞いだのは 2 つで、観測した失敗形は 7 つあった

ADR-123 で Q6 (Draft の実装先行) と Q2 の trigger 拡張は入った。残りは散文である:

| 失敗形 | 実例 | ADR-123 直後の問い所 |
|---|---|---|
| 新しい register が別の記法で生える | ROADMAP そのもの | **無い** |
| 索引と header の Status が食い違う | ADR-032 | **無い** (実測でまだ 3 件残っていた) |
| 文法・規則の書き写し (第二のパーサ) | `adrStatuses()` | CODE_CONTRACTS の散文のみ |
| 条件つき退役が実行されない | Phase S-4 → BFF Phase D 表 | **無い** |

散文に書いた規則は誰も開かない (原則 #19 Q3)。ADR-123 は自分でそう書きながら、
自分が見つけた失敗形の半分を散文に置いて出荷していた。

### 力学 3 — 「満期が来る」は「片付く」ではない

DEF-021 の満期を `満期=GONE:docs/ROADMAP.md::未移管` と書いたとき、前回の説明は
「移管して節を消せば決着」だった。**これは誤りである。** GONE が発火する = **検査が
落ちる**であって、片付くのではない。正しい運用は:

1. 14 件を Issues へ移す → 2. §未移管 を消す → 3. **次の CI で Q2 が落ちる** →
4. DEF-021 の行を消し baseline を下げる → 5. 緑

つまり trigger は**決着し忘れを止める装置**である。この誤解は運用の説明そのものに
出たので、登録簿に書き下す (満期の定義は「片付いた」ではなく「**片付いたかを問う
べき時が来た**」)。

## Options considered

- **A: baseline を上げ続けて運用する** — tradeoff: 安い。しかし Q1 の失敗メッセージが
  毎回ノイズになり、「上がったから確認する」という反応が摩耗する。指標が壊れている
  ことを知りながら残すのは、ADR-115 の「印字された数は検査ではない」の裏返し
  (**読まれない検査は印字と同じ**) になる。
- **B: 散文を書いた文書を `EXCLUDED` に足す** — tradeoff: 最も直接的だが、Yellow Cards
  の 1 例目がまさにこれを禁じている (手書きの除外表は、母集団を持たない表が一段下に
  生えたもの)。しかも ADR を書くたびに除外表が伸びる。
- **C: `src/` `scripts/` だけ数える** — tradeoff: 単純で 0 へ向かえる。しかし
  ADR-027 / 032 / 015 / 017 へ移設したばかりの宣言が全部見えなくなる — ADR-123 D1 が
  「残しの内容の正本は決定を所有する ADR」と決めた直後にその正本を母集団から外す。
- **D: 文書構造で絞る【採用】** — 残しは「残りの作業を宣言する節」に書く、という
  規則にし、その節の下だけを数える。tradeoff: narrative に書いた残しは見えなくなる。

## Decision — Strategy (§1.2 Strategy)

### D1 — `docs/**` は「残りの作業を宣言する見出し」の配下だけ数える

見出しの文言 (`残し` / `Deferred` / `Future Work` / `Out of scope` / `Open questions` /
`引き受けなかったもの` …) から導出する。**手書きの除外表を作らない**のが要点で、
キーワードは見出しの**先頭付近** (12 文字以内) に無ければならない — 後ろに現れる語は
主題ではなく修飾である。`src/` `scripts/` は全行 (コードに narrative は無い)。

副産物として **「残しをどこに書くか」が入口 1 つに定まる** (原則 #1)。

**限界 (宣言する — 推論させない):** narrative に本物の残しを書くと見えない。これは
交換条件であって事故ではない — 見えなくなる代わりに数が 0 へ向かえる。反対側からは
Q3 / Q4 (登録簿の行が実在を問う) と Q6 が押さえる。

### D2 — Q7: 別の記法で書かれた register を数える

優先度マーカーの**表**を持つ文書は既定 0。正当なものは `DECLARED_PRIORITY_TABLES` に
理由つきで宣言する。ROADMAP は 29 行を持ちながら語彙ヒット 0 件で母集団の外に居た
(ADR-123 §力学 1) — **語彙を 1 語ずつ足す経路では記法の違いに届かない**ので、
記法そのものを数える。

**限界:** 捕まえるのは**この記法だけ**である。次が `[P1]` や `TODO(high)` や外部
ツールのリンクで生えたら見えない。記法の集合を先回りで網羅することはできない
(できるならそもそも ROADMAP の 29 行は見えていた)。これは一般解ではなく、
**観測された記法を 1 つ塞ぐ**ものである。

### D3 — 索引と header の Status を突き合わせる

ADR-032 は header `Proposed` / 索引 `Accepted` / 実装 13 ファイルの三様ずれを 4 か月
続けていた。**どちらの読み方でも見えない** — header だけ読めば「まだ提案中」で筋が
通り、索引だけ読めば「採択済み」で筋が通る。**2 つを突き合わせる者が居なかった**だけ。

比較するのは TOKEN 部分だけにする。注記は索引のほうが厚いのが正常で、そこまで一致を
求めると索引が header の複製になる (§1.1 — 索引は導出物)。

### D4 — Status を読む文法が 1 つであることを数える

ADR-123 §実装で分かったこと 2 の再発防止。CODE_CONTRACTS に規則を書いたが散文は
誰も開かない — **数えるべきは在るパーサではなく、`adr-status.mjs` の外に在る
パーサの個数**である (原則 #19 Q3)。

### D5 — 満期 trigger の意味を登録簿に書き下す

「満期が来る」= 検査が落ちる = **片付いたかを問うべき時が来た**であって、
「片付く」ではない。DEF-021 の trigger も一意なマーカーへ張り替える
(`未移管` は ROADMAP に 2 箇所あり、節だけ消して案内文を残すと発火しなかった)。

## Consequences — Evidence と tradeoff (§1.2 Evidence)

**Evidence:**

- `pnpm test:deferrals` — **宣言外 99 → 1**。残る 1 件は順序表が*この検査自身を記述
  している*文で、既知の偽陽性として焼いた。宣言済み 21 行 / 満期が機械可読 9 件。
- **初回実行で DEF-025 を掘り出した** — `ADR-076 §Still deferred` の「TS 側 HTTP 往復
  conformance は public 配線回で追加」は **5 か月**そこに在ったが、99 件の散文に
  埋もれて誰にも見えていなかった。指標を直すと、直した指標が仕事を始めた。
- **Q7 が初回実行で 2 つ目の記法を見つけた** — `docs/validation/2026-03-22-phase-c.md`
  の P1〜P4 勧告表 6 行。凍結する前に実体を確認し、唯一のコード項目 P1
  (`_applyGeometryUpdate` のガード) は `src/service/SceneService.js:373` に実装済みと
  確認した。
- **D3 が実測で 3 件の食い違いを出した** (ADR-007 / 009 / 036)。ADR-036 は header
  `Accepted` / 索引 `Partially Superseded by ADR-040` で、**ADR-040 §Supersedes が
  ADR-036 を名指ししている**ので索引が正しく header が古かった。
- **変異で確認済み** — ADR-091 の索引 Status を `Accepted` に書き換えると D3 が名指しで
  fail し、復元で緑。`commit-meta.mjs` に Status パースの正規表現を 1 行足すと D4 が
  fail し、復元で緑。

**Tradeoff (引き受けたもの):**

- **narrative の残しは見えない** (D1 の限界)。
- **Q7 は 1 つの記法しか見ない** (D2 の限界)。
- **Q1 の baseline 1 は偽陽性である。** 0 にするには順序表の散文を書き換えるしかなく、
  それは検査に合わせて履歴を消す行為なのでしない。**正当な非ゼロとして宣言する**。

### 引き受けなかったもの (宣言する — 推論させない)

- ~~**条件つき退役** (「X が完成したら Y を削除」) の検出~~ → **ADR-125 で決着 (2026-08-12)**。
  当時「語彙を足せば捕まるが ADR-123 §力学 1 が否定した手」と書いたのは正しく、実測でも
  削除動詞 × 条件マーカーの 2 要素で 87 hit のほぼ全部が偽陽性だった。答えは検出ではなく
  **義務の置き場所**で、`Retires:` を ADR ライフサイクルの欄にした (ADR-125)。
  ここで「今日は設計していない」と宣言したことが、次の ADR の入口になった。
- **Issues レーンの個数**は依然 CI が数えない (ADR-123 D2 の限界宣言のまま)。

## Lens notes

- **原則 #19 Q3 (どこで問われるか)** — この ADR の中身はほぼ全部 Q3 である。
  ADR-123 は失敗形を 7 つ見つけて 2 つしか機械に降ろさず、残り 5 つを散文に置いた。
  散文に置いた規則は守られない、と同じ ADR の中で書きながら。
- **原則 #31** — 「悪化の速度」には欄が無い。baseline が上がったこと自体は記録されるが、
  **上がり続けていること**はノードを持たない。だから 71 → 99 は「今回も上がった」に
  見えて、「この数はもう 0 へ向かえない」には見えなかった。
- **§1.1** — D3 は索引と header という 2 つの写しを突き合わせる。本来は源が 1 つで
  あるべきだが、索引は人が読む導出物として実用上要る。**複製を消せないなら、
  ずれを検出する**というのが次善であり、その次善を機械に持たせた。
