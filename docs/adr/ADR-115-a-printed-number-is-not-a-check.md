# 115. 印字された数は検査ではない — 観測トレーラの欠測に境界と予算を与える

- Status: Accepted (実装済み 2026-08-08 — `scripts/check-commit-trailers.mjs` の **4 つ**の問いが CI gate で走る。欠測 14 件を ratchet で固定、母集団の境界は git 履歴から**導出**し、境界を決定できないこと自体を fail にした)
- Date: 2026-08-08
- Deciders: yuubae215, Claude
- Supersedes / Superseded by: **ADR-092 §4 を補完する** (置き換えない — §4 の「塞げない穴は数える」という*決定*は正しく、欠けていたのは*数える機械*だった)

## Context — Goal と力学 (§1.2 Goal)

**Goal:** *観測の被覆率が、印字ではなく検査として問われる。* トレーラを持たない
コミットの個数がいつでも数えられ、増えた瞬間に機械が落ちる。

出発点はユーザーからの「コミットメッセージから評価するスクリプトを実行して最近の
傾向を評価して」という指示である。`metrics:commits` を走らせた結果、**傾向より先に
母集団のほうが壊れていた**。以下はすべて実測で、散文の転記ではない。

### 力学 1 — 「数える」は宣言されたが、読む機械が居なかった

ADR-092 §4 はこう書いている:

> 取りこぼしは `report` の `with Model-Effort: N / 総数` として**母数に現れる**。
> 不在を推測させず、数えて宣言する。

決定は正しい。しかし CI (`.github/workflows/ci.yml`) が走らせていたのは
`pnpm test:commit-meta` — **導出規則の単体テストだけ**である。`metrics:commits` を
読む step は、どの workflow にも 1 つも無かった。

つまり数は印字されていたが、**誰も見ていなかった**。「数える」と*宣言したこと*と、
その数を*読む機械が在ること*は別の事実である。これは ADR-109 D6 が
「満期を*書く欄*を作ったことと、その欄を*読む機械*が在ることは別」として
既に踏んだ形の再生産で、今回は**観測装置そのもの**が原則 #31 を踏んだ。

実測: hook 導入 (2026-07-25, `76b2db6`) 以降 56 コミット中 **14 件が無トレーラ**。
被覆 75%。誰も気づいていなかった。

### 力学 2 — 欠測はコミット単位、抑止はセッション単位

欠測はランダムに散らばっておらず、**連続ブロック**だった:

| ブランチ | 内訳 |
|---|---|
| `claude/ia-redesign-1xzsxz` | 1 本目のみ刻印 → **10 本連続で欠測** (26 時間) |
| `claude/gsn-implementation-order-xbshq1` | 1 OK → 1 欠測 |
| `claude/link-network-layout-physics-pypual` | 1 欠測 → 1 OK |
| `claude/adr-unimplemented-design-97b30n` | 1 OK → 1 欠測 |
| `claude/unimplemented-adr-design-vsar1k` | 1 OK → 1 欠測 |
| `claude/adr-100-...-c0j5cm` / `phase-3-adr-tickets-lb82w4` | 3 本とも OK |

機構はスクラッチ repo で**再現済み** (同じ hook スクリプトをそのまま実行):

| ケース | 形 | 結果 |
|---|---|---|
| A | `git commit` のみ (push は別呼び出し) | `claude-opus-5/high` ✅ |
| B | `git commit ... && git push` を 1 コマンド | 空 ❌ |
| C | push 済みブランチへの 2 本目 (連鎖なし) | `claude-opus-5/high` ✅ |

C が通るので「ブランチの 2 本目以降が落ちる」ではない。**コマンドの形だけ**が効く。
連鎖すると PostToolUse は push の後に発火し、hook の
`git branch -r --contains HEAD` が非空になって `exit 0` する (ADR-092 §4 が
「塞げない」と正しく予告した穴そのもの)。

ブロック状になる理由は穴の存在ではなく**抑止の粒度**にある。PreToolUse の助言は
`$TMPDIR/cc-commit-trailers/<session>.chain` で「1 セッション 1 回」に絞られている。
**欠測はコミットごとに起きるのに、警告はセッションごとに 1 度**なので、一度その形を
採ったセッションは警告を 1 回受けたあと以降すべてを静かに落とす。助言の頻度を
上げても解けない — 助言は非ブロックであり、PreToolUse は commit の前なので
そもそも刻めない。**だから計数が要る。**

### 力学 3 — 空の母集団は「全件 OK」と区別がつかない (この棚卸し自身が踏んだ)

この調査は shallow clone (`--depth` 付き) の作業ツリーで始まった。`report` の
1 行目はこう出た:

```
commits (no-merges): 82   with Model-Effort: 42
```

82 は全履歴 947 の **13% の切片**である。分母が履歴の一部でしかないことは、
出力のどこにも現れない。`git fetch --unshallow` して初めて 947 になった。

これは欠測と同型の欠陥である: **母集団が空/部分であることは、それ自体がノードを
持たない**。CI の `actions/checkout` は既定が shallow なので、素朴に検査を足すと
「境界コミットが履歴に無い → 母集団 0 件 → 欠測 0 件 → 緑」という、**最も静かな
無検査**が出来上がっていた。検査を書く側が同じ盲点を踏む。

### 力学 4 — 被覆率だけを見ると緑のまま空洞化する

hook は transcript が読めなくても `unknown/unknown` を**宣言**する (ADR-092 の
正しい設計 — 不在を推測させない)。だが被覆率の分子はそれを「刻印済」と数える。
transcript の読み取りが静かに壊れると、**被覆 100% のまま中身が空**になる。
「トレーラが在るか」と「トレーラが何かを言っているか」は別の問いである。

## Decision

### 1. 欠測を数える検査を CI gate に載せる (Q3 — 成果物は散文ではなくチェック)

`scripts/check-commit-trailers.mjs` が 4 つを問う。`pnpm test:trailers` = 純粋関数の
単体テスト + 実履歴に対する census。gate ジョブの step として走る。

| 問い | 数えるもの | 予算 |
|---|---|---|
| **Q1 RATCHET** | 母集団のうちトレーラを持たないコミットの個数 | **14** — 超えても**下回っても** fail |
| **Q2 POPULATION** | 母集団の境界を実際に決定できたか | 決定不能なら fail |
| **Q3 DEGRADED** | `unknown/unknown` / 片翼だけの個数 | 0 |
| **Q4 DRIFT** | 根拠 (transcript) と申告 (`Co-Authored-By`) の食い違い | 0 |

### 2. 母集団は導出する — 日付も SHA も書かない (ADR-102)

境界は `.claude/hooks/commit-trailers.sh` を**追加したコミット**を git 自身から引く。
それ以前は「刻めなかった」のではなく「**刻む主体が居なかった**」ので、母集団の外に
在るのが正しい。正当な 0 を推論させず境界として宣言する。

初回の集計で私はここを間違えた: `--since 2026-07-25` (日付) で数えて、同じ日の
hook 導入**前**の 3 コミットを欠測に数え、71% と報告した。正しくは 75% である。
日付は境界の近似であって境界ではない。

著者が Claude でないコミットも母集団の外。hook は人間のコミットに**意図的に**
刻まない (帰属 — ADR-092 §2) ので、欠測に数えれば偽陽性になる。`classifyCommit` は
`missing` と `foreign` を別の値として返し、`summarize` は `foreign` を**分母にも
入れない**。

### 3. 予算は ratchet で、超えても下回っても fail (ADR-100 と同形)

`MISSING_BASELINE = 14`。「宣言外は 0 であるべきだが今は 14 ある」を隠さず定数にする。
下回ったときも落とすのは、下げ忘れた余白に次の 1 件が隠れるからである。

### 4. 母集団を決定できないことを **fail** にする (力学 3 への答え)

境界コミットが履歴に見つからなければ、0 件を報告して緑を出すのではなく落ちる。
CI 側は gate の checkout に `fetch-depth: 0` を足した。浅くすると**赤くなる** —
黙って無検査になるのではなく。

### 却下した案

- **(A) `report` の出力を grep して閾値を見る。** 出力の書式が契約になり、母集団の
  定義が `report` と gate の 2 箇所に散る (§1.1 違反)。導出規則は
  `commit-meta.mjs` の純粋関数から import し、数え方は新しい純粋関数に閉じた。
- **(B) 穴自体を塞ぐ (stamping を `prepare-commit-msg` へ移す)。** 有効だが**別の
  決定**であり、しかもそれ単独では足りない: `core.hooksPath` の設定が落ちれば同じ
  無言の失敗が戻るので、結局この計数が要る。順序として計数が先。**DEF-012 として
  宣言し、満期を ADR-116 に置いた** (この ADR の中に散文として置くと、力学 1 を
  そのまま再生産することになる)。
- **(C) 助言を毎コミット出す。** 粒度は直るが助言は非ブロックのままで、
  PreToolUse は commit の前なので刻めない。うるさくなるだけで欠測は残る。

## Consequences

- **Evidence (§1.2):** `pnpm test:trailers` が (1) 分類規則の単体テスト 11 件、
  (2) 実履歴に対して母集団 56 件・刻印済 42・欠測 14 (baseline 14)・空洞 0・
  申告ズレ 0 を報告する。
- **変異で確認済み (緑が本物か):** (a) `MISSING_BASELINE` を 13 にすると Q1 が
  「14 件に増えた」で fail、15 にすると「下げること」で fail、(b) `--depth 1` の
  shallow clone で走らせると Q2 が母集団を決定できず fail、(c) 完全クローンでは
  同じコマンドが通る (負の対照の対照)。いずれも復元で緑に戻る。
- **この検査自身が一度素通りした (記録として残す — ADR-114 と同じ扱い):**
  初版の Q2 は「境界が**見つかったか**」だけを問うていた。`--depth 1` のクローンでは
  そこに在る最古のコミットが親を持たないため、**あらゆるファイルがそこで「追加された」
  ように見える** — `--diff-filter=A` はそれを素直に返し、境界は HEAD 自身に化けた。
  結果、母集団 1 件・欠測 0 件になり、**Q1 が「`MISSING_BASELINE` を 0 に下げろ」と
  指示した**。落ちてはいたが落ち方が嘘で、指示に従えば検査は永久に無力化される。
  「見つからない」より「**間違ったものが見つかる**」ほうが静かに危険である
  (ADR-103 の退役の腐敗が緑を出すのと同じ構図で、こちらは*もっともらしい赤*を出す)。
  修正は `populationVerdict` に 3 つ目の判定 `truncated` を足したこと — 親を持たない
  境界が正当なのは**本物の root コミット**のときだけ。**力学 3 を、力学 3 を直すために
  書いた道具の中で再生産していた。**
- **波及 (blast radius):** 新規 `scripts/check-commit-trailers.mjs` +
  `scripts/check-commit-trailers.test.mjs` + `package.json` の `test:trailers`
  + CI gate の step と checkout の `fetch-depth`。**`src/` は 1 行も触っていない。**
  既存の hook・`commit-meta.mjs` の挙動は変えない。
- **穴は残っている。** この ADR は欠測を*塞いだ*のではなく*可視にした*。連鎖した
  コミットは依然として刻めず、次に起きたら CI が赤くなる (= 直すか宣言するかを
  迫られる)。塞ぐ側は DEF-012 / ADR-116。

## Lens notes

- **§1.1 真実の源は一つ:** 分類規則 (レイヤ写像・conventional type) の正本は
  `commit-meta.mjs` のまま。この検査は**数え方**だけを持ち、導出は import する。
- **原則 #31 の n 例目:** ADR-102 (表の分母) / ADR-103 (退役した形) / ADR-109
  (残し) / ADR-114 (画面に入らなかった入口) に続く。原則は既に在るので**追加しない**
   — 足すのは検査だけ。今回の新しさは、**原則 #31 の道具を作る側が同じ盲点を
  踏んだ**こと (力学 3): 母集団が空であることは、母集団を辿っても出てこない。
- **§1.4 状態台帳:** 「コミットの観測メタデータ」の行は `docs/STATE_LEDGER.md` に
  既に在る (ADR-092)。基数列の「0 = ... `report` の母数に現れる」という記述が
  **まさに空洞だった**ので、同じコミットで更新した。0 が 3 種類 (人間 / 境界の外 /
  欠測) に分かれること、状態集合に 4 つ目の `空洞` が要ることも、この作業で出た
   — どちらも「在るか無いか」では足りない欄である。
