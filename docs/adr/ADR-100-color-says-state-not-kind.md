# 100. 色は「実体の種」ではなく「状態」を語る — 既定サーフェスを中立にし、アクセントを 1 つに畳み、宣言外の色を ratchet で止める

- Status: Proposed
- Date: 2026-07-26
- Deciders: yuubae215, Claude (pairing)
- Supersedes / Superseded by: なし (ADR-065 Phase 0 が作った `theme/tokens.js` の統治を、語彙の宣言から**使用の強制**へ広げる)

## Context — Goal と力学 (§1.2 Goal)

当事者の観測 (本人が「好みが混じる」と明示したもの):

> ・キューブのデフォルトカラーをグレーにして、アクセントカラーをオレンジにしたい。
> カラースキームが飽きやすいカラーになっている気がする。これによりカラースキームを
> 全体的に見直したほうが良いのであれば見直してほしい。

要件が**解の形**で来ているので Goal へ持ち上げる (§1.2)。「グレーとオレンジ」は
好みだが、その下に測定可能な性質がある:

- **G1 — 画面の彩度は *状態* に配られ、*既定* には配られない。** 何も起きていない
  ときの画面は落ち着いており、色が付いているものには意味がある。
- **G2 — 1 つの意味には 1 つの色。** 「いま操作の対象である」を表す色が
  画面上で 1 つに定まる。
- **G3 — 色の語彙は宣言され、宣言の外の色が増えない。**

### 力学 1 — 図と地が同じ色相にある (「飽きやすい」の機構)

既定シーンの実測:

| 要素 | 色 | 出所 |
|------|----|------|
| キューブ本体 | `#4fc3f7` (シアン) | `MeshView.js` の `BODY_COLOR` — **リテラル、トークン外** |
| 背景グラデーション / フォグ | 濃紺〜青紫 | `SceneStage` |
| 地面グリッド | `#444466` / `#222244` | `SceneView._setupGrid()` — リテラル |
| 選択中の実体の emissive | `#112244` | `MeshView.js` — リテラル |

**主役 (実体) と背景が同じ青系にある。** 図と地が色相を共有しているので、
キューブは「空の一部」として読める。さらに `BODY_COLOR` の `#4fc3f7` は
`COLOR.accentActive` (「Active tool / indicator cyan」) と**同一の hex** である。
つまり同じシアンが「これは実体だ」と「これはいま有効なツールだ」の両方を言って
いる。常に全面が彩度を持ち、かつその彩度が何も区別しないので、**強調に使える
色が残っていない** — これが「飽きやすい」の構造的な中身である。

### 力学 2 — 「選択されている」を表す色が 3 つある

| 場所 | 色 | 宣言 |
|------|----|------|
| Outliner の選択行 | `rgba(255,112,67,0.18)` / 文字 `#ff8c69` (オレンジ) | **トークン外** |
| 「選択されたコントロール」 | `COLOR.accent` = `#5c5cff` (青紫) | トークン |
| 3D の選択ハイライト | シアン系 (`#4fc3f7` 族) + emissive `#112244` | トークン外 |
| CF の選択 | 原点球 `#ffcc00` (金) | トークン外 |

当事者の「アクセントをオレンジにしたい」は、実は**既に存在する事実の追認**である
— Outliner はすでにオレンジで選択を表しており、トークンが宣言する `accent` と
食い違っている。好みと構造が同じ方向を指している。

### 力学 3 — 語彙は守られているが、使用は守られていない

`src/theme/tokens.js` は `docs/LAYOUT_DESIGN.md` の表と**両向き**にピン留めされて
いる (`tokens.test.js`: 表 → COLOR、COLOR → 表)。語彙の無言の増殖は塞がれている。
塞がれていないのは**使用**の側:

| 指標 | 実測 (`src/**/*.js`) |
|------|--------------------|
| 色リテラルの出現 | **420 箇所** |
| 相異なる色 | **150 色** |
| `COLOR` の語彙 | **21 色** |

具体例が病を示す: `COLOR.measure = #f5a623` が宣言されているのに、実コードは
**`#f9a825` を 13 箇所**で使っている (`MeasureLineView` / `OutlinerView` /
`MeasurePlacementHandler` / `Outliner.jsx`)。同じ「計測」という意味に、宣言された
色と宣言されていない色がある = §1.1 の第二の源が、トークンを作った後にも生き残って
いる。

理由は `tokens.js` 自身が書いている統治にある:

> Opportunistic migration rule: any line you TOUCH that carries a hex literal
> present in this palette must be rewritten to consume the token.

これは**誰も開かない散文**ではないが、**誰も問わないルール**である (憲法 Q3)。
「触った行だけ」は書く瞬間に問われないので、触らない 400 行は永遠に残る。
ADR-065 Phase 0 は語彙にはチェックを与え、使用には与えなかった。

### 位置

View 層 + `src/theme/`。ドメイン・契約・コアAPI には触れない。
Layout/Context DSL の意味色 (`LINK_TYPE_COLORS`、ペルソナ配色、注釈のカテゴリ色) は
**データが持つ意味**なので本 ADR の「状態の色」とは別扱いにする (下記 Decision 5)。

## Options considered

- **A: 定数を 2 つ変える (`BODY_COLOR` → 灰、`accent` → 橙)** — tradeoff: 当事者の
  要望は最短で満たせる。だが「選択」の 3 色は 3 色のまま、宣言外の 130 色も
  そのまま残るので、次の機能追加で同じ濁りに戻る。今回の観測はまさに「ADR-065
  Phase 0 の後に濁った」結果である。
- **B: 役割トークンを導入し、既定を中立へ・アクセントを 1 つへ畳み、宣言外の色を
  ratchet で止める (採用)** — tradeoff: 触る箇所が多く、1 PR では終わらない。
  移行の途中状態を明示的に許す仕組みが要る。
- **C: 本格的なデザインシステム (テーマ切替・彩度ランプ・コントラスト保証・
  ライトモード)** — tradeoff: 現時点でテーマ切替の要件は無い。トリガの立って
  いないレンズを起こすのは過剰モデリング (核 §5)。
- **D: 現状維持** — tradeoff: G1〜G3 未達。当事者の「飽きやすい」は主観だが、
  その下の「図と地が同色相」「1 意味 3 色」「宣言外 130 色」は客観的な欠陥。

## Decision — Strategy (§1.2 Strategy)

**案 B。** 好みの部分 (灰とオレンジ) は当事者の指定どおり実装し、その指定が
**構造として保たれる**ようにする。

### 1. トークンを「値の名前」から「役割の名前」へ

今日の `COLOR` は半分が役割名 (`bgPanel` / `border` / `danger`)、半分が**値の名前**
(`fxGreen` / `fxAmber` / `fxBlue` / `accentActive`) である。値名のトークンは
「意味が変わっても名前が追随しない」ので、第二の源と同じ病を持つ
(`fxGreen` を橙にしたら名前が嘘になる → 誰も変えられなくなる)。

役割語彙へ寄せる:

| 役割 | 意味 | 当事者の指定 |
|------|------|-------------|
| `surface` / `surfaceRaised` / `surfaceSunken` | クロームの地 | 現状維持 |
| `entityDefault` | **実体の既定サーフェス** | **中立グレー** (新設) |
| `accent` | **いま操作の対象である** (選択・アクティブ) | **オレンジ** |
| `factTone` / `cautionTone` / `dangerTone` / `infoTone` | 結果の証明・警告・破壊・情報 | 現状の fx 族を役割名へ改名 |
| `axisX` / `axisY` / `axisZ` | ROS 慣習の予約色 | **変えない** (源は外部規約) |

### 2. 彩度は状態にだけ配る (G1)

- 実体の既定サーフェスは中立グレー。**色が付いている = 何かの状態がある**。
- 背景・グリッドは低彩度のまま (図と地の色相分離は、地ではなく**図を中立へ寄せる**
  ことで達成する — 背景の作り込みは ADR-067 の boot 演出の資産なので壊さない)。
- 選択・ホバー・アクティブは `accent` の強度違いで表す。

### 3. 「1 意味 1 色」を規則にする (G2)

`accent` は**選択/アクティブ専用**とし、Outliner の行・3D のハイライト・
N パネル・LINK NETWORK の focus・モバイルツールバーのアクティブがすべて
同じトークンを引く。今日の 4 色 (橙 / 青紫 / シアン / 金) は 1 つになる。

逆向きの規則も置く: **1 つの hue を 2 つの意味に割り当てない**。`accent` を
オレンジにすると `measure` (琥珀) と `fxSnap` (橙) が近接するので、実装時に
どちらかを hue ごと動かす。どれを動かすかは実装の色決めだが、**近接を許さない
のは規則**である。

### 4. 使用を機械で問う — ratchet (G3 / 憲法 Q3)

`tokens.test.js` を拡張し、`src/**` の**宣言外 hex リテラルの個数を数える**。
一度に 0 にはできないので **予算方式 (ratchet)**:

- 現在値をベースライン定数として**明示的に宣言**し、
- 実測値がそれを **超えたら fail**、下回ったら「ベースラインを下げよ」と促す。

これが「触った行だけ移行」という誰も問わないルールの、**書く瞬間に問われる形**への
翻訳である。数えるのは*在るトークン*ではなく**宣言の外にある個数**であることが
要点 (原則 #31 — 在るものを辿る検査は、宣言外の色を素通りする)。

### 5. 「意味の色」は本 ADR の対象外と**宣言**する

`LINK_TYPE_COLORS` (リンク種)、`PERSONA_PALETTE` (アクター)、注釈カテゴリ色は
**データが持つ意味**であり、UI の状態色ではない。これらは別の語彙として
`theme/` に分離し、ratchet の分母からも分けて数える。「対象外」を書かないと、
次に数えたときにこの 3 つが宣言外として現れて、規則が空回りする
(原則 #29 の「全ワイヤは契約ありか明示的対象外宣言かの二状態」と同じ形)。

## Consequences — Evidence と tradeoff (§1.2 Evidence)

- **肯定的:**
  - G1 — 既定画面が落ち着き、色が付いているものに意味が戻る。当事者の
    「飽きやすい」に対する構造的な回答になる (主観の解消は別途 dogfooding)。
  - G2 — 「選択されている」が画面のどこでも同じ色になる。窓が増えても増えない。
  - G3 — 宣言外の色が単調減少する。ADR-065 Phase 0 が語彙に与えた保証と同じ
    強度の保証が、使用側にも付く。
  - 当事者の指定 (灰・オレンジ) がトークン 2 行として表現され、後から
    「なんとなく別の青」が混ざることを機械が止める。
- **受け入れるコスト / 否定的:**
  - **ratchet のベースラインは「今日の 130 色を許す」という宣言**である。
    緑でも画面は当面まだら。隠さずそう宣言する (減点を承知で数える方が、
    数えないより強い)。
  - 中立グレーの実体は「地味」「安っぽい」に振れうる。反証されうる仮説であり、
    テストでは閉じない。反証されたら「中立サーフェス + マテリアル (反射・陰影) で
    質感を出す」方向へ回収する — 色相で主張を取り戻す方向へは戻さない
    (それは G1 の放棄になる)。
  - `fx*` トークンの改名は 40 箇所以上に触れる。改名だけの PR にして、
    色の変更と混ぜない (レビューで「意味が変わったのか名前が変わったのかが
    分からない」を避ける)。
  - コントラスト比を測っていない。中立グレーの実体 + 暗い背景は、選択ハイライトの
    コントラストを落としうる。実装時に最低比を決めて数える。
- **検証 (証拠):** 論証木は `docs/gsn/adr-100-color-says-state.gsn`
  (goal ごとの支えの正本はそちら)。起票時点の証拠は**すべて未来形**であり、そう
  宣言する。実装時に閉じる予定の検査:
  - **宣言外リテラルの ratchet (単体)**: `src/**` を走査し、宣言外 hex の個数が
    ベースライン以下。ベースラインは定数として宣言し、対象外語彙 (Decision 5) は
    分母から除く。**現在値 420 出現 / 150 色 / うちトークン 21** を初期記録として
    テストのコメントに残す (減ったことを後から言えるようにする)。
  - **1 意味 1 色 (単体)**: 「選択/アクティブ」を描く箇所が `accent` トークン
    以外の色を持たないこと。*在る箇所*を辿るのではなく、選択を描く**種類を列挙**
    して数える (Outliner 行 / 3D ハイライト / CF 原点球 / N パネル /
    LINK NETWORK focus / モバイルツールバー)。
  - **hue 近接の検査 (単体)**: 役割トークン同士の色相角が既定の閾値以上離れて
    いること。`accent` と `measure` / `cautionTone` の衝突を機械で止める。
  - **コントラスト (単体)**: `entityDefault` / `accent` / テキスト各色の
    コントラスト比が閾値以上。
  - **`LAYOUT_DESIGN.md` の表との両向きピン留め**は既存のまま維持 (第三の源を
    作らない)。
  - 当事者による dogfooding (`docs/dogfooding/`) — 「飽きにくくなったか」は
    主観なので、証拠は当事者の記録であり、そう宣言する。
- **波及 (blast radius):** `src/theme/tokens.js` (役割語彙)、
  `src/theme/tokens.test.js` (ratchet + 1 意味 1 色 + hue 近接 + コントラスト)、
  `docs/LAYOUT_DESIGN.md` § Color Palette (表の改訂)、
  `src/view/MeshView.js` (`BODY_COLOR`・選択 emissive)、
  `src/view/SceneView.js` (グリッド)、`src/view/OutlinerView.js` /
  `src/components/Outliner/Outliner.jsx` (選択行)、
  `src/view/CoordinateFrameView.js` (原点球)、`src/view/LinkNetworkView.js`
  (focus)、`src/view/MeasureLineView.js` ほか `#f9a825` の 13 箇所、
  `src/controller/UIStateManager.js` / 各 handler の `setStatusRich` 色。
  契約・BFF・`core/` は不変。

## Lens notes

- **要件が解の形で来た (核 §3 のトリガ):** 「グレーとオレンジ」は解。持ち上げた
  Goal は「彩度を状態にだけ配る / 1 意味 1 色 / 語彙の宣言」。持ち上げた結果、
  当事者の好みは**既存の矛盾の解決**と一致していた (Outliner は既にオレンジ)。
  好みだから採る、ではなく、好みと構造が同じ方向を指しているから採る。
- **§1.1:** `#f5a623` と `#f9a825` は「計測」という 1 つの事実に対する 2 つの源。
  トークンを作っただけでは第二の源は消えず、**使用側に検査を置いたときに消える**。
- **原則 #31:** 数えるのは在るトークンではなく、**宣言の外にある個数**。
  「宣言外は 0 であるべきだが今は 130 ある」を明示的に宣言する ratchet は、
  正当な非ゼロを推論させず宣言させる形。
- **原則 #30 との関係:** 色は動きではないが、統治の形は同じ — 所有者・予算・
  削減経路。ratchet が予算、役割トークンが所有者、ベースライン低下が削減経路。
