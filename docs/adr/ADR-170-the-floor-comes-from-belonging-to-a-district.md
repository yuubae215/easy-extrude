## Context — Goal と力学

ADR-097 以来、床 (Z=0 を割らない) は**実体の種類**で決まっていた (Solid・ImportedMesh・
robot_base は `grounded`)。床は「誰も宣言していない 1 つ目の床」で、どこにも名前が無い。
当事者の構想では、マップオブジェクトは 2 つの役を持つ:

- **Lynch の都市像** (ADR-026): District は「性格を共有する区域」。物はどれかの区域にある。
- **工場の階**: 将来フロアを分ける。物はどれかの階の床に立つ。

「物を置く前にマップオブジェクトを定義させる」をそのまま入れると、一手目 (Empty テンプレの
最初の Box) で詰まる。

**Goal:**
- **G1** 物がどこに属し、どの床に立つかが、場所の宣言として文書に残る (種類から推測しない)。
- **G2** 何も定義していないシーンでも、最初の一手が詰まらない。
- **G3** 床の高さが 1 か所 (地区) から来るので、後でフロアを分けるときに新しい床の源を足さない。

## Decision

- **D1 — 重なりは導出。** 実体の足元が地区と同じ高さで面積的に重なっていれば、その地区と
  「重なっている」。重なる地区はすべて数える。地区どうしも重なってよい。保存しない (足元の
  関数 — ADR-097 D2 の支持と同じ作り)。
- **D2 — 所有者の違う地区の重なりは交渉に回す。** 同じ所有者なら何もしない。違えば
  ADR-049 の衝突として表に出し、交渉クラスターに入れる。描くことは止めない。
- **D3 — 所属は宣言。** `地区 —contains→ 実体` (SpatialLink の `contains` — ADR-038 の
  領域の包含。新しい語は足さない、原則 #33)。重なりとは別の事実で、地区の外へ動かしても
  外れない。外にいる間は「所属しているが地区の外」を状態として見せる (ADR-168 D4 と同じ形 —
  止めない)。地区の上へ動かしたときに所属を提案する (ADR-168 S2-1 と同じ流れ)。
- **D4 — 床は所属から来る。** 地区に所属している実体は、その地区の高さに床を持つ
  (方針の入口・`_policyDelta`・ADR-169 の回転と押し出しはこの床に効く)。どこにも所属して
  いない実体は床を持たず、Z<0 にも置ける。そのとき「Below ground level」の知らせは残す
  (止めない)。**地区が 0 個のシーンでは全実体が床を持たない** — 何も定義しなくても最初の
  一手は詰まらない (G2)。種類ごとの `grounded` (Solid・ImportedMesh) は退役する (Retires)。
- **D5 — 1 つの実体は 1 つの高さにしか所属できない。** 高さの違う地区への所属は、同じ実体が
  2 つの階に在ることになるので拒否する (理由を出す — 原則 #11)。同じ高さなら複数所属してよい。
- **D6 — 地区は高さを持つ。** 床の Z は地区の欄。既存のシーンは地区 0 個 (= 床なし) として
  読む。フロアは「同じ高さの地区の集まり」として導出できる形にしておき、フロアの実体は
  この ADR では作らない (G3)。地下は負の高さの地区である。

```
overlaps(e)  = { d | d.z = z(e) ∧ area(footprint(e) ∩ d) > 0 }      — 導出 (D1)
belongs(e)   = { d | d —contains→ e }                                  — 宣言 (D3)
invariant    : |{ d.z | d ∈ belongs(e) }| ≤ 1                          — D5
floorZ(e)    = belongs(e) = ∅ ? none : the one d.z                     — D4
```

## 決まっていないこと

O1・O3 は S2 の俯瞰で当事者が決めた (2026-11-07): **O1 = 例外にしない (所属で床を決める)**、
**O3 = S キーは残す (所属して床をもらっている物を、あえて床下に置く宣言として)**。下は起票時の問いの記録。

- **O1 — ロボットの台座 (決定: 例外にしない)。** robot_base は Solid ではなく CoordinateFrame (`robotRole: base`) で、
  今は種類で `grounded`。理由は `placement.js` のコメント 1 行 (「床に埋まった base pose をコアAPI
  へ送っても解は無意味」— ADR-083 を引いているが ADR-083 の本文には床の記述が無い)。地下は今も
  S で床下を宣言すれば置ける。D6 で地下が負の高さの地区になるなら例外は要らない、というのが
  起票時の案。決まれば Retires に robot_base の行を足す。
- **O2 — 地区の所有者とは誰か。** 描いた人か、所属を主張した人か (ADR-168 D5 の主張者 `by` と
  同じ語で持てるか)。名乗りの瞬間は DEF-074 が残している。
- **O3 — S キー (床下の宣言) の行き先 (決定: 残す — 床を持つ物の床下の宣言)。** 地下が地区で言えるなら、所属している実体の床下
  (基礎・杭) だけが S の役に残る。残すか、地区へ寄せるか。

## 段

- **S1 語彙と文書** (実装済み 2026-11-07): ゾーンの高さ (D6)、所属 = `contains` (D3)、D5 の検査。
  重なりの導出 (D1) は使う側 (交渉) と一緒に S3 へ移した (俯瞰 Q4)。
- **S2 床の入れ替え** (実装済み 2026-11-07): 方針を種類から所属へ (D4)。`PosePolicyOwnership.test.js` の母集団に
  「床を持つか」の決定を入れる。既存シーンの読み (地区 0 = 床なし) の移行。
- **S3 提示**: 重なりの導出 (D1)、所有者の違う重なりの交渉 (D2)。所属の提案と「地区の外」の状態 (D3) は
  既存の推論 (`SemanticInferencer` の Contains) と `contains` の違反 (「Escaped outside the Zone」) が既に持っていた —
  S3 で足すのは、それを所属の語で言い直すことだけ。

各段は `/whiteboard` の §0〜§6 を出して合意を得てから実装する (CLAUDE.md §ADR の段の実装)。

## 却下した案

- **物を置く前に地区を描かせる**: 一手目で詰まる (G2)。
- **敷地を 1 つ宣言して始める**: 何も定義しないシーンに床を作ることになり、D4 の「床は所属から」
  と食い違う。当事者の答え (地区 0 なら Z<0 可) がこの案を置き換えた。
- **床は地区の中にだけ在る (重なりで決める)**: 地区の端から物をはみ出させた瞬間に床が消える。
  所属の宣言なら物について回る。
- **高い方の地区の高さを取る**: 描き順で同じ物が上下する。D5 で多重の高さそのものを拒否する。

## 実装メモ (S2 — 2026-11-07)

俯瞰 (`/whiteboard`) で当事者が合意した読み (Q1〜Q4 は推奨どおり、O1・O3 は上の決定):

- **Q1 `grounded` を割る。** `grounded` は「床を割らない」と「面に載る物体 (水平ドラッグ・積み上げ補助)」の
  2 つの事実を 1 語で運んでいた。床を外した物体を `free` にすると、箱がカメラ正対面で動き、積み上がらなくなる。
  後者を方針の語 **`resting`** (Solid・ImportedMesh・robot_base)、前者を物の **床** =
  `floorOf()` (`src/domain/zone.js` — 属するゾーンの高さ、所属が無ければ `null`) にした。純粋な決定
  (`resolvePlacementDelta` / `resolveFaceExtrudeDistance`) は床を引数 `floorZ` で受け取り、Z=0 を知らない。
  `hasGroundInvariant` は答える問いが「載る」だけになったので `restsOnSurfaces` に改名した。
- **Q2 床の無い物も操作感は変えない。** 積み上げ補助と水平ドラッグは方針 (`resting`) に残る。地面 Z=0 は
  「載る面」として残す (注釈は `supported` のまま、補助は地面にも座らせる)。ゆえに地区 0 個のシーンで Z<0 へ
  行くのは、補助が退く Z 拘束の Grab か、S で補助を切ったとき。
- **Q3 床が物の上へ後から来ても動かさない。** 所属を宣言した・ゾーンを上げた・Region をゾーンにしたとき、
  物は動かず、守る床は `min(floorZ, 開始時の底)` — 沈めないが引き上げない (ADR-169 の押し出しと同じ規則)。
  次の掴みで床まで跳ねる形 (ADR-169 の症状) を、床が動いた側から再発させない。
- **Q4 知らせ。** 床を持つ物は「Below its zone floor (Z < h mm)」、床の無い物は従来の
  「Below ground level (Z < 0)」(`checkGroundClearance` が床ごとに測る)。
- **O3 の帰結。** `setBelowGradeIntent` は床を持つ物にだけ書く。床の無い物の S は補助を切るだけで、
  **宣言を書かないのでジェスチャを越えない** — 次の掴みは Stack から始まる (ADR-097 G3 の「宣言はジェスチャを
  越えて残る」は床を持つ物の規則になった)。床を失った物 (contains を消した) に残った旗は読みでは `false`。
- **既存シーンの読み (移行)。** scene / Layout の schema は変えない。ゾーンに属していない物はすべて床を持たない
  (地区 0 = 床なし — D6)。テンプレ (`examples/`) にはゾーンがあるが `contains` が 0 本なので、読み込みの挙動は
  変わらない。`_adoptBelowGradeIntent` は「属するゾーンの床より下」で読み直す。
- **スケッチの押し出し。** スケッチから生まれる Solid はまだどこにも属さない (所属の提案は S3) ので床を持たず、
  下向きの押し出しは止まらない (ADR-169 は種類で Z=0 に止めていた)。問いは `allowedProfileHeight` に残し、
  ゾーンの中に生まれる日が来たら規則を足さずに床が効く。

**俯瞰より踏み込んだところ (原則 #19):** (1) 純粋な決定 (`resolvePlacementDelta` / `dragPlaneNormalFor`) が
方針語の外の値で throw するようにした。`PLACEMENT.GROUNDED` を消したとき、テストに残った 3 か所
(= `undefined`) が「free 以外は水平」の分岐を素通りして緑を出したため — 退役の腐敗は緑を出す (原則 #31)。
(2) 並進は**ゾーンから先に**方針を当てる。所属物の床は、同じジェスチャで動くゾーンなら「開始時の高さ + ゾーンに
与えた delta」で読む (`_gestureElevationReader` — 書いている最中の板を読まない、原則 #24)。**ただしいまの画面には
ゾーンと所属物を同時に選ぶ入口が無い** (ゾーンの板は cuboid を持たず矩形選択から外れ、Outliner に追加選択が無い)
ので、この経路は走らせて確かめていない。(3) ロボットの差分ペアの e2e (ADR-098) は、X の掴みで押した S が
Y の掴みにも効くこと (= 宣言) を当てにしていた。床の無いロボットでは S は宣言しないので、2 つ目の掴みでも押す形に直した。

**問い所:** `src/PosePolicyOwnership.test.js` — 床の決定 (`floorOf`) を引くのは `_floorZOf` ただ 1 本で、pose 決定の
閉包に居ること / 閉包の中で板の高さを読むのは `_policyDelta` (ゾーン自身) と `_gestureElevationReader` だけ /
押し出し・床下の宣言・読み込み・知らせが `_floorZOf` を通ること / `zonesOf` を zone.js の外で呼ばないこと /
`PLACEMENT.GROUNDED`・`'grounded'` が src に 0 個。2 つ目の床の読み手を足すと落ちることを確認した。
`src/domain/placement.test.js` が `grounded` の不在と方針語の外の throw を問う。
