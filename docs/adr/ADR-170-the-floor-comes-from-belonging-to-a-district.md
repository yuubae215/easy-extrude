## Context — Goal と力学

ADR-097 以来、床 (Z=0 を割らない) は**実体の種類**で決まっていた (Solid・ImportedMesh・
robot_base は `grounded`)。床は「誰も宣言していない 1 つ目の床」で、どこにも名前が無い。
当事者の構想では、マップオブジェクトは 2 つの役を持つ:

- **Lynch の都市像** (ADR-026): District は「性格を共有する区域」。物はどれかの区域にある。
- **工場の階**: 将来フロアを分ける。物はどれかの階の床に立つ。

「物を置く前にマップオブジェクトを定義させる」をそのまま入れると、一手目 (Empty テンプレの
最初の Box) で詰まる。

**Goal:**
- **G1** 物がどこに属し、どの床に立つかが、場所の宣言として文書に残る (種類から推測しない)。
- **G2** 何も定義していないシーンでも、最初の一手が詰まらない。
- **G3** 床の高さが 1 か所 (地区) から来るので、後でフロアを分けるときに新しい床の源を足さない。

## Decision

- **D1 — 重なりは導出。** 実体の足元が地区と同じ高さで面積的に重なっていれば、その地区と
  「重なっている」。重なる地区はすべて数える。地区どうしも重なってよい。保存しない (足元の
  関数 — ADR-097 D2 の支持と同じ作り)。
- **D2 — 所有者の違う地区の重なりは交渉に回す。** 同じ所有者なら何もしない。違えば
  ADR-049 の衝突として表に出し、交渉クラスターに入れる。描くことは止めない。
- **D3 — 所属は宣言。** `地区 —contains→ 実体` (SpatialLink の `contains` — ADR-038 の
  領域の包含。新しい語は足さない、原則 #33)。重なりとは別の事実で、地区の外へ動かしても
  外れない。外にいる間は「所属しているが地区の外」を状態として見せる (ADR-168 D4 と同じ形 —
  止めない)。地区の上へ動かしたときに所属を提案する (ADR-168 S2-1 と同じ流れ)。
- **D4 — 床は所属から来る。** 地区に所属している実体は、その地区の高さに床を持つ
  (方針の入口・`_policyDelta`・ADR-169 の回転と押し出しはこの床に効く)。どこにも所属して
  いない実体は床を持たず、Z<0 にも置ける。そのとき「Below ground level」の知らせは残す
  (止めない)。**地区が 0 個のシーンでは全実体が床を持たない** — 何も定義しなくても最初の
  一手は詰まらない (G2)。種類ごとの `grounded` (Solid・ImportedMesh) は退役する (Retires)。
- **D5 — 1 つの実体は 1 つの高さにしか所属できない。** 高さの違う地区への所属は、同じ実体が
  2 つの階に在ることになるので拒否する (理由を出す — 原則 #11)。同じ高さなら複数所属してよい。
- **D6 — 地区は高さを持つ。** 床の Z は地区の欄。既存のシーンは地区 0 個 (= 床なし) として
  読む。フロアは「同じ高さの地区の集まり」として導出できる形にしておき、フロアの実体は
  この ADR では作らない (G3)。地下は負の高さの地区である。

```
overlaps(e)  = { d | d.z = z(e) ∧ area(footprint(e) ∩ d) > 0 }      — 導出 (D1)
belongs(e)   = { d | d —contains→ e }                                  — 宣言 (D3)
invariant    : |{ d.z | d ∈ belongs(e) }| ≤ 1                          — D5
floorZ(e)    = belongs(e) = ∅ ? none : the one d.z                     — D4
```

## 決まっていないこと

- **O1 — ロボットの台座。** robot_base は Solid ではなく CoordinateFrame (`robotRole: base`) で、
  今は種類で `grounded`。理由は `placement.js` のコメント 1 行 (「床に埋まった base pose をコアAPI
  へ送っても解は無意味」— ADR-083 を引いているが ADR-083 の本文には床の記述が無い)。地下は今も
  S で床下を宣言すれば置ける。D6 で地下が負の高さの地区になるなら例外は要らない、というのが
  起票時の案。決まれば Retires に robot_base の行を足す。
- **O2 — 地区の所有者とは誰か。** 描いた人か、所属を主張した人か (ADR-168 D5 の主張者 `by` と
  同じ語で持てるか)。名乗りの瞬間は DEF-074 が残している。
- **O3 — S キー (床下の宣言) の行き先。** 地下が地区で言えるなら、所属している実体の床下
  (基礎・杭) だけが S の役に残る。残すか、地区へ寄せるか。

## 段

- **S1 語彙と文書**: 地区の高さ (D6)、所属 = `contains` (D3)、D5 の検査、重なりの導出 (D1)。
- **S2 床の入れ替え**: 方針を種類から所属へ (D4)。`PosePolicyOwnership.test.js` の母集団に
  「床を持つか」の決定を入れる。既存シーンの読み (地区 0 = 床なし) の移行。
- **S3 提示**: 所属の提案と「地区の外」状態 (D3)、所有者の違う重なりの交渉 (D2)。

各段は `/whiteboard` の §0〜§6 を出して合意を得てから実装する (CLAUDE.md §ADR の段の実装)。

## 却下した案

- **物を置く前に地区を描かせる**: 一手目で詰まる (G2)。
- **敷地を 1 つ宣言して始める**: 何も定義しないシーンに床を作ることになり、D4 の「床は所属から」
  と食い違う。当事者の答え (地区 0 なら Z<0 可) がこの案を置き換えた。
- **床は地区の中にだけ在る (重なりで決める)**: 地区の端から物をはみ出させた瞬間に床が消える。
  所属の宣言なら物について回る。
- **高い方の地区の高さを取る**: 描き順で同じ物が上下する。D5 で多重の高さそのものを拒否する。
