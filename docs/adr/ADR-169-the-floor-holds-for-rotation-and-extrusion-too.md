## Context — Goal と力学

ADR-097 は「床を割らない」を `grounded` の不変条件にしたが、それを強制するのは並進の
入口 `applyPreviewTranslation` だけだった。床の clamp は「動かした瞬間に、底面が床を割らない
最小の Z へ引き上げる」形なので、**床を割った状態を作る入口が 1 つでもあると、次の Grab の
最初のフレームで跳ねる**。2026-11-01 に直した「床に半分埋まって生まれる立方体」がこの形の
1 例目で、残りを実アプリで測った:

| 入口 | 修正前 (実測) | 次の Grab |
|---|---|---|
| R → X → 45 | 底面 Z = −20.71 | +20.7mm 跳ねる |
| R X 45 の後、別ジェスチャで R X −45 | 底面 Z = +20.71 (浮く) | stack assist で 20.7mm 落ちる |
| Edit ▸ 上面を E で −150 | 底面 Z = −50 | +50mm 跳ねる |
| スケッチを −100 で押し出し | 底面 Z = −100 (宣言の無い床下) | +100mm 跳ねる |
| Ctrl+ドラッグの即時回転 | `AppController` が `obj.rotate` を直接呼ぶ = 回転の入口が 2 つ | — |

**Goal:** 床の不変条件はどの入口を通っても成り立つ (ADR-097 G1 を pose だけでなく形にも)。
跳ねる・浮く・落ちるは「不変条件が後から効く」症状であり、制約そのものの問題ではない。

## Decision

- **D1 — 回転: 載っていた物は載ったまま回る。** セグメント開始の写しで底面が何かに載って
  いた (`supportUnder` — 床でも他の実体でも) なら、回転後も底面をその高さに保つ (持ち上げも
  下げもする)。浮いていた物は従来どおり中心で回る。最後に `_policyDelta` が床の clamp を当てる
  (宣言された床下は素通し)。入口は `SceneService.applyPreviewRotation` ただ 1 つ — Ctrl+ドラッグも
  ここを通す。
- **D2 — 押し出し: 床で止まる。** 面押し出し・スケッチの押し出しは、Grab と同じく床で止める
  (持ち上げない — 底面を下へ引いた人に「本体が上へ逃げる」を返すのは要求の符号を裏返す)。
  床下は G → S で宣言してから。決定は純粋関数 `resolveFaceExtrudeDistance` (`domain/placement.js`)、
  入口は `applyPreviewFaceExtrude` (方針あり) / `restoreFaceExtrude` (cancel・undo・redo の復元 —
  方針なし) / `allowedProfileHeight`。スケッチの押し出しが床で 0 になったら確定せずに
  「Stopped at ground level」を出してスケッチへ戻る (原則 #11)。

```
回転:   rotated = rotate(segStart, ΔQ)
        seat    = resting(segStart) ? bottom(segStart) − bottom(rotated) : 0
        lift    = policy(rotated, (0, 0, seat))          ← grounded: z ≥ −bottom(rotated)
押し出し: 面の各頂点 z_k + n_z·d ≥ min(0, z_k)  を満たす区間へ d を clamp
```

### 却下した案

- **回転でも持ち上げるだけ (D1 の初版)**: 実装して測ると、回して戻す 2 回目のジェスチャで
  20.7mm 浮き、次の Grab で落ちた。上げられるが下げられない規則は、跳ねる向きを裏返すだけ。
- **回転を床で止める (角度を clamp)**: 回したい角度に回らない。回転は床を割る意図の表現ではない。
- **押し出しで床を割ったら警告 + 床下を自動で宣言**: 「気づいたら潜っていた」と「潜ると決めた」の
  区別 (ADR-097 G3) がそこで消える。
- **Stack (床) を明示的にオンにさせる**: 既定を自由にすると、真上からは見えない沈みが判定の
  入力に混ざる。よくある方 (床の上) を既定にし、例外 (床下) に宣言を求める ADR-097 を保つ。

## Consequences

- 床下の基礎を押し出しで作るには、先に G → S で床下を宣言する手順が要る (下向きの押し出しは
  宣言が無い限り床で止まる)。
- 床で止まったこと自体の合図 (押し込んで止まったときの床の光など) はまだ無い — Grab も同じ。
  別の判断として残す。
- 問い所: `src/PosePolicyOwnership.test.js` が `extrudeFace` とスナップショット回転を書く場所を
  `SceneService` だけに限り (修正前のコードで 7 件を検出)、3 つの入口が方針を引いていることを
  逆向きに固定する。決定の表は `src/domain/placement.test.js`。
