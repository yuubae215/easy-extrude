# 121. 重心は宣言された事実であり、推定は別レーンである — 仮定を値に化けさせない

- Status: Proposed (未実装 — ADR-118 と同じ PR で起票。ADR-120 が先に要る)
- Date: 2026-08-11
- Deciders: yuubae215, Claude
- Supersedes / Superseded by: なし (ADR-056/077 の動詞境界を重心へ、ADR-060 の kind union を request 側へ)

## Context

いまの `grasp_stability` は **進入ベクトルと法線の内積** = 正対度しか見ていない。
偏心した対象を端で掴む危うさは原理的に表現されていない。把持安定性の実質的な入力である
**重心が契約のどこにも無い**。

ADR-118 で吸引が入ったことで、これは「あったほうがいい」から**「無いと吸引の判定が
成立しない」**へ格上げされた。カップ軸から重心がずれているぶんがモーメントになり、
シールを剥がす向きに働く。吸引にとって重心はチャックより**直接効く**。

要件はこう出た: 「重心 (そのままは入力できないから、なにに近いか？とか材質とか
大きさとかからの推定？)」。**推定**という語がこの ADR の中心になる。

## Decision

### D1 — ワイヤが運ぶのは「誰かが決めた重心」と、その出所

`target.centerOfMass` を **kind 判別の有界 union** で足す (ADR-060 と同じ形):

- `{ kind: "measured", point }` — 実測 / CAD 由来。そのまま信じる。
- `{ kind: "assumedHomogeneous", point }` — 均質仮定 = 図心。**仮定であることが値と
  一緒に運ばれる**ので、クライアントはそう表示できる。

リクエスト側の追加なので `contractVersion` は上げない (ADR-083/084)。

### D2 — 欄ごと不在のとき、図心へ黙って倒さない

これが本体。図心へ倒すと**仮定が値に化けて、画面は実測と区別できなくなる** —
ADR-090 の「原点に立つ無限リーチの幽霊ロボット」と同じ形である。不在のときは
重心依存の objective を**評価しない** (ADR-120 の規律にそのまま乗る)。

`assumedHomogeneous` を既定で入れる案も検討した。常に評価できるので分母問題が起きない
利点はあるが、実測と仮定の区別が `kind` だけになり、見落とされたときに静かに実測として
扱われる。**明示的に選ばれた仮定**と**誰も考えなかった不在**を区別できることのほうを取る。

### D3 — 推定は propose レーン、契約には乗らない

材質・寸法・「何に近いか」から重心を提案するのは ADR-056/077 の **propose** 側:
`core/recommendation/` のレーン、あるいはフロントの決定的な計算 (均質仮定の図心は
純粋な幾何計算なので決定的 core で足りる)。**提案は真偽値を返さない**し、ワイヤにも
乗らない。乗るのは、人か決定的な規則が**採った**結果だけ。

材質 → 密度のような対応が要るなら、それは `QUOTIENT_TABLE` と同じ**キュレーション辞書**
として決定的 core に置く (行を足せばその語は決定的になる、という既存の拡張点)。

### D4 — 重心を使う判定は新しい objective として足す (`grasp_stability` は変えない)

`grasp_stability` の意味を書き換えると既存の応答値が黙って変わる。`com_offset` (仮) を
別 objective として足せば、重み付けされたときだけ計算され、重心が無ければ ADR-120 の
規則で自然に「評価していない」になる。

## Consequences

### 得られるもの

- 吸引の判定が成立する。カップ軸と重心のずれをモーメントとして扱える。
- 「この値は測ったのか仮定なのか」が画面で言える。dogfooding の記録 (既定値の獲得) が
  仮定由来の値を実測として拾わなくなる。

### 払うもの

- **ADR-120 に依存する。** 先に入れないと、重心不在で `com_offset` が評価できないだけで
  全候補のスコアが下がり、比較可能性が壊れる。順序は 120 → 121。
- 均質仮定の図心は**箱にしか出せない**。いまの対象表現 (中心 + 寸法 + 回転) が箱なので
  図心 = 中心で自明だが、メッシュが来たら別の計算が要る。
- 推定レーンそのものは、この ADR では作らない (置き場所を名指しするだけ)。

### 検証 (証拠) — 未実装

| 主張 | 問い所 (予定) |
|------|-------------|
| 不在が図心へ倒れない | 重心なしのリクエストで `com_offset` の鍵が**出ない**こと |
| 仮定と実測が区別される | 同じ点でも `kind` が違えば表示が違うこと (純粋層) |
| 推定がワイヤに乗らない | 契約スキーマに推定由来の欄が無いこと (census) |
