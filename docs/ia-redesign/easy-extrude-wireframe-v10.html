② 主張する人に保全者を足した(当事者の訂正)。v8〜v9 の行は設計側の 3 人(vision / robot / mech)だけで、 セルを受け取って毎日使う人がいなかった。重みを主に動かすのはエンドユーザ = 自動化工程の保全者で、 その重み付けがいちばん重要かつ外してはいけない。語彙は既に在る — Context DSL の actor role に maintainer がある(VALID_ROLES)。無かったのは行列の行だけ(原則 #33)。
③ 保全者の行は最上段に固定し、優先を語で持つ。「外してはいけない」は数値の重み付け(保全者 ×2 など)ではなく 人どうしの関係なので、行の印 ★優先 として持つ(原則 #33 (3) — 束どうしの優先は要素の数値に散らさない)。

⚠ v10 に残した引っかかり
保全者は、設計しているあいだ、たいていその場にいません。セルは設計・立ち上げを経てから保全者に渡ります。 いちばん重要で外せない重みの持ち主が、重みを決める時期に不在なのです。
[保全者が不在] を押すと、行列の保全者の行が空になります。このとき — 設計側の誰かが代わりに書くのか (それは「既定値で埋める」と同じ形で、原則 #31 が禁じている)、保全者の行が空のまま問うことを許すのか (答えは「保全者の基準ではない答え」になる)、それとも空なら問えないのか。 どれを選んでも、保全者が後から来たとき、それまでの答えをどう扱うかが一緒に決まります。
