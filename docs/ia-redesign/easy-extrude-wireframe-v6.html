v5 → v6 の変更点(3件)
① カウンタを 3 つに割った。合意が要る理由は 2 つあり、性質が逆: 衝突(制約の共通部分が空 = 技術的必然。放置すると決まらない)と 提案(他人の所有物を変えたい = 社会的必然。放置しても現状のまま進む)。 さらに未所有(誰も名乗っていない)を第 3 のカウンタに。同じ数に足すと、 片方が減っても安心できない。
② 承認は「証憑」なので消えない。「変えたけど良いって言ったよね?」を残すのが承認の主目的の一つ。 承認は Decision(decidedBy / rationale / proposed → agreed)として記録され、 既存の Why タブ(φ⁻¹ の来歴読み出し)でそのまま辿れる。 ここから取り下げの範囲が導かれる —— 取り下げられるのは未承認の提案だけ。 承認済みを変えたければ新しい提案を出す。未解決カウンタは減り、決定の履歴は増える一方。
③ 所有者 0 に警告。「所有者なし」は 1 つの状態に見えて 3 つが潰れている: 本当にいない / 名乗り忘れ / 誰が名乗るかのチキンレース。 正当なのは 1 つだけなので既定値で埋めず、正当な 0 は宣言させ、宣言されていない 0 は警告する (原則 #31 / ADR-100 の ratchet と同じ形)。宣言すると未所有カウンタから外れる。

⚠ v6 に残した引っかかり(次の反復のタネ)
① 提案は 3D からしか出せません — 非対称です。他人の実体を動かすのは提案にできるのに、 他人の主張区間(右パネルの 🔒 の行)はそもそも触れないので提案すら出せません。 でも「相手の設計を変えたい」という行為は同じはずです。数値側にも 「この値にしませんか」= 提案の導線が要りませんか? (要るなら 🔒 は「編集不可」ではなく「直接編集不可・提案可」という別の状態になります)
② 承認ボタンを誰でも押せます。証憑の価値は「所有者が良いと言った」ことなので、 承認は所有者の鍵を持つ人だけが押せるべきでは? いまは鍵 0 でも承認できてしまい、 decidedBy に書く名前の根拠がありません。
③「衝突 3」だけ緑になりません。提案と未所有は 0 にできるのに、衝突を解消する導線 (場の Cluster 承認)が繋がっていない。減らせないカウンタは、無視される訓練になります。
