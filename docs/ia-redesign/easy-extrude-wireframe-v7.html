v6 → v7 の変更点(3件。v6 の引っかかり 3 つをすべて回収)
① 「直接編集不可・提案可」を第三の状態にした。他人の主張区間は 🔒 で触れなかったが、 実体を動かすのは提案できるのに数値は提案すらできないのは非対称だった。 いま行は 3 状態:直接編集可(自分・枠+内側の影)/ 直接編集不可・提案可(他人・[✎ 提案])/ —。実体でも数値でも規則は 1 つ:鍵があれば確定、なければ提案。
② 承認は所有者の鍵を持つ人だけ。証憑の価値は「所有者が良いと言った」ことなので、 誰でも押せると decidedBy に書く名前の根拠がない。無効時は理由を明示する (repo の disabled-as-quest — 無効フラグとその理由は同じ述語の返り値から来る。無言の no-op は禁止 #11)。 衝突の解消は関与する全員の鍵が要る(既存の n-ary 合同確定と同じ)。
③ 衝突と提案を同じライフサイクルに畳んだ。 「開催されるまではただの戻り値、開催後は歴史」から規則が 1 行で出る —— 導出値は保存しない。人の行為は保存する。衝突は文書から毎回導出できるので保存すると 第二の源になる(§1.1 / 原則 #24)。「議題にする」「これで良い」は人の行為なので残す。 帰結:場の議題 = 議題化された衝突 ∪ 提案。カウンタも ≈ 衝突(揮発) / ⚑ 議題(場にある) / ◇ 未所有 の 3 本に整理された。

⚠ v7 に残した引っかかり(次の反復のタネ)
① 提案の内容が空です。いま「✎ 提案」は提案したという事実だけを作り、 どの値にしたいのかを運んでいません。承認する側は「良いって言ったよね?」の何を承認したのか 分からない —— 証憑としては不完全です。提案は差分(現在値 → 希望値 + 理由)を持つべきでは? 持つなら、それは Decision の rationale にそのまま入ります。
② 議題化した衝突を「やっぱり議題から外す」導線がありません。提案には取り下げがあるのに、 衝突の議題化は一方通行です。開催そのものが人の行為(=歴史)なら、 「議題にしたが結論を出さずに閉じた」も歴史のはず —— 消すのではなく 「未決のまま閉会」として証憑に残すのが筋ではありませんか?
③ 鍵を全部持つと、この設計は何も止めません。兼務者(鍵 3 つ)は提案を経ずに全部確定できます。 それは正しい —— でも証憑が一つも残りません。1 人で全部決められる状況こそ 「あとで誰も経緯を辿れない」状態です。単独決定にも記録が要りますか?
