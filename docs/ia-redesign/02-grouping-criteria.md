## 採用した基準: 検証の主体は単数か複数か

> 検証されているのは**値ではなくクライテリアの食い違い**であり、
> **食い違いは1人の視野の中には存在しない**。

- **単数**(自分の入力を自分の基準で測る) → 計算で出せる → **戻り値**
  対象の隣に、常時、待たずに出る。
- **複数**(各ステークホルダーの*暗黙の*クライテリアとのギャップ) → 計算で出せない → **場**
  集まる場所が要る。`Matrix` が actor × variable の行列である理由そのもの。

つまり住所は**対象の性質ではなく、クライテリアの所有者の数**で決まる。

### 系: 共有 KPI は「場」まで待たせない (shift-left)

場まで待つと収束が場の往復回数に比例する。CI が起こしたことと同型:

| | 統合 (旧) | 統合 (CI 後) |
|---|---|---|
| gap の判明 | 結合テストフェーズ (場) | push 直後の赤/緑 (戻り値) |
| 収束 | 場の往復回数だけかかる | 場に来る前にほとんど潰れている |
| 場 | — | **消えない。議題が変わる** |

したがって:

- **戻り値 = gap を発見する**(早く・自動・全員に同時に)
- **場 = gap を解消する**(交渉・決定・承認)

現状の渋滞は、**発見と解消を同じ場でやっている**ことに由来する。

## 却下した物差し ①: 入力 → 出力 → 検証(直線)

**反証は判断そのもの。** `4 Robot を置く`(入力)と `37 Grasp Search`(検証)は
直線で切ると別グループ = 遠くに置かれる。しかし両者は同じループの中にいる:

```
置く → 届くか見る → 置き直す → …
```

**現行 UI はこの直線を忠実に実装した姿である** — AddMenu(左上)と
`Context ▾` の奥のタブ(右端・4クリック)。**ワークフローを直線に写すと、
ループの両端が必ず最も遠くなる。** 直線が病気であって薬ではない。

核 §1.3「プロセス様態 (BPMN vs CMMN)」— 形の取り違えは付随的複雑性の常習的な源。
このアプリには**両方の様態が入っている**:

- **CMMN 的**(探索・裁量・ループ) — 置く / 動かす / 押し出す / 届くか見る
- **BPMN 的**(目標駆動・順序あり) — Wizard / Intake / テンプレ開始 / 承認フロー

現在この2つは**同じ 280px のタブ列に同居**している(`Wizard` の隣が `Grasp`)。

## 却下した物差し ②: 「場所か戻り値か」の二択

偽の二分法。対象の性質ではなく所有者の数が効くので、同じ「検証」でも両側に分かれる。

## UI が優先する層: 意味 > 幾何

> UI としては意味の層を優先する。幾何はバックエンドの役割。

これはリポジトリの憲法 (CLAUDE.md) と**同型**:

> `src/` は解法を持たない。IK / 干渉 / リーチ / 把持安定性の *解き方* は `core/` に
> のみ書く。フロントは DSL で参照名を**宣言**し、結果は契約経由で受け取って**表示**する。

→ **画面の構造をアーキテクチャの層構造と同型にできる**(住所を議論で決めなくてよくなる)。

### 帰結: 現状は主従が逆

| | 担当する層 | 現在の待遇 |
|---|---|---|
| Outliner | 幾何 / TF 階層 (ADR-094 以降は文字通り TF spanning tree) | 左 **200px 常設**・主ナビゲータ |
| Link Network | **意味** (SpatialLink = cotree edges + 注釈) | 左下 220px・リンク 0 本で自動消滅・Context 中は強制非表示 |

意味の層が、自分から隠れる隅のパネルに置かれている。

### 裏付け: マップ要素は関係グラフの一要素(実装で確認)

`src/controller/AppController.js:1813-1822` — `_updateLinkNetwork` は
`scene.objects` 全件を走査し、Lynch 注釈をノード種別として流し込む:

```js
: obj instanceof AnnotatedLine   ? 'annot-line'
: obj instanceof AnnotatedRegion ? 'annot-region'
: obj instanceof AnnotatedPoint  ? 'annot-point'
```

Map で描く要素と関係グラフは、仕様上も**実装上も**同じ 1 つのグラフ。

## 基準を当てた結果(機能 25〜37)

```
[入力]        31 Wizard  32 Assets  33 Intake  34 自然言語取込
              └ そもそも検証ではない → 「置く」側へ

[戻り値=発見]  28 Checks  29 Why  37 Grasp  36 RegionGhosts
              └ 計算で出る。対象の隣に、常時、待たずに出るべき

[場=解消]      26 Cluster(承認)  27 Questions(他者に答えてもらう)
              35 Author(交渉しながら動かす)
              └ 所有者が複数。集まる場所が要る
```

### 検出した違反

**28 Checks は共有 KPI そのもの**(全員が見るべき合否)= 最も戻り値であるべきもの。
現在の住所は `Context ▾ → New Project → テンプレ選択 → 交渉オーバーレイ → Checks タブ`
(しかも doc が checks を宣言しないとタブ自体が現れない)。
**共有 KPI が最も場に縛られた場所にある** — 上の原則からの直接の帰結として逆。

**32 Assets の発見可能性** — 作者本人が UI から到達できることを認識していなかった
(`ContextController.js:677` の `enterNegotiation` は文書未ロードだと warn トーストで
行き止まり。実際の経路は `New Project` 経由の最短 4 クリック)。原則 #16
「発見可能性は成果物である」の違反。住所が**タスクの近さではなく実装された時期と場所**で
決まった証拠 (ADR-063 Phase 4 が Context の文脈で作られたため `ContextLayer` のタブになった)。

**タブ列の物理的破綻** — `ContextLayer.jsx:133-152` はタブを `flex:1` で並べる。
パネル幅 280px / タブ 10 枚 = 1 枚 28px、`padding: 6px 2px` を引くと文字に 24px。
`fontSize: 10px` の `Overview` は約 45px 必要で**物理的に入らない**。
